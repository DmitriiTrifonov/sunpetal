# AGENTS.md — Sunpetal

Статический рекомп DS-версии Flower, Sun, and Rain (Europe, `YHNP`) в нативное приложение. Рантайм на Rust, лицензия Apache-2.0. Документы на русском, коммиты и код: комментарии коротко, по делу.

Заметки проекта дублируются в Obsidian-vault: `~/Documents/synced-vault/synced-vault/03 Проекты/Sunpetal (рекомп)/` (там же журнал и инструменты). Правила vault — в его `AGENTS.md`.

## Прочитать первым делом

1. `docs/PLAN.md`: этапы 0–12, что сделано (`[x]`).
2. `docs/STATUS.md`: состояние, список недоделок и вопросов.
3. `docs/GPU-BACKEND.md`: план и журнал GPU-бэкенда 3D (этапы 0–9); тут же образец оформления планов и журнала.
4. `docs/BUGS.md`: открытые и закрытые баги (`B-NN`), снимки в `artifacts/` (не в git).
5. `docs/RECON-NDSKIT.md`, `docs/PRIOR-ART.md`: разведка на нашем дампе; существующие рекомпы DS, лицензии, что можно брать.

Остальные документы: `docs/ABI.md` (шов C ↔ Rust), `docs/BUILD.md`, `docs/ANDROID.md`, `docs/TRANSLATING.md`, `docs/TRANSLATION-RECON.md`, `docs/PS2-RECON.md`, `docs/RECON-WIDE.md`, `docs/RECON-SCREENS.md`, `docs/debug-tools.md`, `docs/TOOLS.md`, `docs/CHECKLIST.md`, `docs/THIRD-PARTY.md`.

## Решения (не пересматривать без причины)

- База: **DS-версия**. PS2 — источник текстур и моделей (этап 7: текстуры, 2D-фоны, модели `MODL`), логика и код только DS. Рекомпы PS2 нет.
- Экраны: игра должна проходиться на **одном экране** (этап 8б: переработка экранов — режим одного экрана, раскладки, пропорции 8в), при этом рендерер получает два экрана отдельными текстурами, раскладка задаётся данными.
- Рантайм и рекомпилятор: **Rust**. Сгенерированный код: сначала **C** (крейт `cc`), потом модули можно переводить на Rust.
- Лицензия: **Apache-2.0**. Код из GPL-проектов (melonDS, dust, legobattles-pc) **не копировать**, только читать. `ndskit` (MIT) брать можно, копирайт сохранять. `ndsrecomp` (PolyForm Noncommercial) только читать.
- Название **Sunpetal**. Не использовать название игры, персонажей, студии, логотипы.
- Ром, образы и всё, полученное из них (извлечённое, сгенерированный код), в репозиторий не коммитить (`.gitignore`).
- Моды (этап 12) позже, но архитектурно: рендерер получает два экрана отдельными текстурами, раскладка задаётся данными.
- Игра берёт данные из `sunpetal.data` (архив, без кода; части: ROM DS обязательна, PS2, перевод, эффекты); запасной путь: подсунуть ROM DS. ROM DS обязателен только для сборки `sunpetal.data`.
- Код игры: приложение с нативным кодом собирает сам пользователь на ПК (вариант «а»); общее приложение с интерпретатором («б») оставлено на потом.
- iOS только сайдлоад/AltStore, в сторы не выкладываем. Репозиторий на GitHub: `DmitriiTrifonov/sunpetal`, CI зелёный.
- Перевод принадлежит автору проекта; в дистрибутив идёт только дельта, без текста оригинала.
- 3D: два движка за одним потоком заданий `Job` — софт (`render3d.rs`, эталон) и GPU на wgpu (`render3d_gpu.rs`, фича `gpu`). GPU обязан совпадать с софтом слово в слово; рассинхрон — баг GPU.

## Как собрать и проверить

Быстрая проверка без ROM: `tools/verify.sh` (сборка, `cargo test --lib`, fmt/clippy советом; `full` — с ROM); её же запускает хук перед `git commit`. Подробные команды — в скиллах: `sunpetal-build-test` (рекомпиляция, самотест, `cargo test`, безголовый запуск), `gpu-parity` (паритет GPU и софта, дампы, слепой прогон). Приложение: `cargo test -p sunpetal-app --release --lib`. Без `generated/recomp` крейт собирается без модулей. На macOS `ndsrun` из `ndskit` не собирается (нужен OpenGL 4.5): графику пишем сами; воспроизведение прогона `ndskit` — `docs/RECON-NDSKIT.md`.

## Правила работы

- Не писать в `~/Developer/games/fsar-ru` (там работающий проект перевода). Из него только читать.
- Чужой код из `ref/` не менять и не коммитить сюда.
- Новые решения и результаты исследований: в `docs/` репозитория и в заметки vault.
- Не убивать запущенную игру пользователя без его слова «перезапуск/перезапусти»; протокол запуска и перезапуска — скилл `window-restart`.
- CI после пуша не проверять каждый раз: смотреть только если пользователь просит или изменение трогает сборку/тесты (код, не документы).
- Скриншоты и кадры для багов — в `artifacts/` (не в git); брать только окно приложения.
- Коммиты только по просьбе пользователя. В конце сообщения коммита: `Co-Authored-By: <имя нейросети, делающей коммит> <её noreply-адрес>` — пишутся имя и адрес той нейросети, которая реально делает коммит, а не другой модели.
- Начатое доводить до конца: задача из нескольких шагов (например, «закоммить и сделать 7.1») выполняется вся, по порядку, в том же ходе — сначала коммит, потом следующий шаг. Не переходить к следующему шагу, пока предыдущий не доведён (файлы записаны, коммит сделан, тесты прогнаны, журнал обновлён). Если шаг требует подтверждения — спросить один раз и по ответу сразу сделать.

- Канбан: `docs/KANBAN.md` (данные `tools/kanban/tasks.json`, `kanban.py render|add|move|p0`). Работаем строго по порядку «Очереди» (сначала P0, потом RICE; ★ — приоритет менеджера: PS2-ассеты, графика, шрифты, ×1,5); в «В работе» не больше трёх. Новую задачу от автора: спросить приоритет, если не ответил — выставить R/I/C/E самому и сказать, куда встала; критичное (падение, потеря сохранения, нельзя пройти, сломана сборка/CI) — сразу P0. Не брать задачу не по порядку без слова автора.
- Замер времени: беря этап или шаг в работу — `python3 tools/roadmap/timelog.py start <id> "название"`, закрывая — `end <id>` (скиллы `plan-steps`, `close-step`); дерево работ — скилл `roadmap-tree`.

## Как разбивать новые планы

Скилл `plan-steps`: разбивка до атомарных шагов, у каждого контрольная точка (КТ авто/ручная), разведка раньше переделки, риск за флагом, закрытие шага — скилл `close-step`. Образец — этап 9 в `docs/GPU-BACKEND.md`. Шаги, проверяемые автономно, идут первыми, с участием автора — в конце.
