Статический рекомп DS-версии Flower, Sun, and Rain (Europe, `YHNP`) в нативное приложение. Рантайм на Rust, лицензия Apache-2.0. Документы на русском, коммиты и код: комментарии коротко, по делу.

## Решения (не пересматривать без причины)

- База: **DS-версия**. PS2 — источник текстур и моделей (этап 7: текстуры, 2D-фоны, модели `MODL`), логика и код только DS. Рекомпы PS2 нет.
- Экраны: игра должна проходиться на **одном экране** (этап 8б: переработка экранов — режим одного экрана, раскладки, пропорции 8в), при этом рендерер получает два экрана отдельными текстурами, раскладка задаётся данными.
- Рантайм и рекомпилятор: **Rust**. Сгенерированный код: сначала **C** (крейт `cc`), потом модули можно переводить на Rust.
- Лицензия: **Apache-2.0**. Код из GPL-проектов (melonDS, dust, legobattles-pc) **не копировать**, только читать. `ndskit` (MIT) брать можно, копирайт сохранять. `ndsrecomp` (PolyForm Noncommercial) только читать.
- Название **Sunpetal**. Не использовать название игры, персонажей, студии, логотипы.
- Ром, образы и всё, полученное из них (извлечённое, сгенерированный код), в репозиторий не коммитить (`.gitignore`).
- Моды (этап 12) позже, но архитектурно: рендерер получает два экрана отдельными текстурами, раскладка задаётся данными.
- Игра берёт данные из `sunpetal.data` (архив, без кода; части: ROM DS обязательна, PS2, перевод, эффекты); запасной путь: подсунуть ROM DS. ROM DS обязателен только для сборки `sunpetal.data`.
- Код игры: приложение с нативным кодом собирает сам пользователь на ПК (вариант «а»); общее приложение с интерпретатором («б») оставлено на потом.
- iOS только сайдлоад/AltStore, в сторы не выкладываем. Репозиторий на GitHub: `DmitriiTrifonov/sunpetal`, CI зелёный.
- Перевод принадлежит автору проекта; в дистрибутив идёт только дельта, без текста оригинала.
- 3D: два движка за одним потоком заданий `Job` — софт (`render3d.rs`, эталон) и GPU на wgpu (`render3d_gpu.rs`, фича `gpu`). GPU обязан совпадать с софтом слово в слово; рассинхрон — баг GPU.

## Как собрать и проверить

```sh
ROM="$HOME/Developer/games/fsar-ru/roms/Flower, Sun and Rain - Murder and Mystery in Paradise (Europe) (En,Fr,De,Es,It).nds"
export PYTHONPATH=$PWD/tools                      # пакет ndskit лежит в tools/ndskit (форк, эмиттер пишет чистый C)
python3 -m ndskit.recomp "$ROM" --out generated/recomp --optest          # ~45 с, C + векторы optest
python3 -m ndskit.recomp.selftest "$ROM" --cpu 9 --auto --out generated/recomp/selftest/arm9_vectors.txt
for o in 1 3 4 5 6; do python3 -m ndskit.recomp.selftest "$ROM" --cpu 9 --overlay $o --auto --out generated/recomp/selftest/arm9_ov${o}_vectors.txt; done
SUNPETAL_ROM="$ROM" cargo test -p sunpetal-runtime   # ~1,5 мин (первая сборка C)
cargo run --release -p sunpetal-runtime --bin sunpetal-headless -- "$ROM" --vblanks 600   # безголовый запуск
```

Без `generated/recomp` крейт собирается без модулей, тесты самотеста не компилируются.

Паритет GPU и софта (нужна фича `gpu`, дампы кадров):

```sh
export SUNPETAL_JOB_DUMPS=$PWD/build/gpu-parity/dumps          # абсолютный путь
cargo test -p sunpetal-runtime --release --features gpu --lib   # 61 тест, должны проходить все
cargo test -p sunpetal-runtime --release --features gpu --lib supersampling_on_dumps -- --ignored   # 32 проверки
SUNPETAL_ROM="$ROM" cargo test -p sunpetal-runtime --release --features gpu --test boot             # кадр в игре, GPU = софт
SUNPETAL_BENCH_DUMP=$PWD/build/gpu-parity/dumps/c18_02_hotel_002521.spjob cargo test -p sunpetal-runtime --release --features gpu --lib bench_supersampling -- --ignored --nocapture
SUNPETAL_ROM="$ROM" python3 tools/gpu-parity/bench_fps.py --vblanks 6000 --scales 1,2 --msaa 0,4   # кадров/с на живой игре
```

Переменные GPU-пути: `SUNPETAL_GPU_TIMING` (отчёт по кадру: атлас, ресурсы, проходы), `SUNPETAL_TILED=0` (вернуть старый последовательный проход прозрачных, по умолчанию тайлы), `SUNPETAL_JOB_DUMPS` (писать/читать дампы). Слепой прогон: `target/release/sunpetal-headless "$ROM" --vblanks 30000 --draw-all --renderer gpu --input "$(cat build/gpu-parity/blind.input)" --save …`, лог `stderr` сравнить с софтовым (`diff`).

Ограничения на macOS: `ndsrun` из `ndskit` не собирается (нужен OpenGL 4.5). Это нормально: графику пишем сами. Воспроизведение исходного прогона `ndskit` (C++, Python-пакет в `~/Developer/games/ref`) — в `docs/RECON-NDSKIT.md`.

## Правила работы

- Не писать в `~/Developer/games/fsar-ru` (там работающий проект перевода). Из него только читать.
- Чужой код из `ref/` не менять и не коммитить сюда.
- Новые решения и результаты исследований: в `docs/` репозитория и в заметки vault.
- Не убивать запущенную игру пользователя (`pkill`, перезапуск): в ней может быть несохранённая игра. Игру для пользователя запускать отдельным процессом без привязки к сессии.
- Скриншоты и кадры для багов — в `artifacts/` (не в git); брать только окно приложения.
- Коммиты только по просьбе пользователя. В конце сообщения коммита: `Co-Authored-By: <имя нейросети, делающей коммит> <её noreply-адрес>` — пишутся имя и адрес той нейросети, которая реально делает коммит, а не другой модели.
- Начатое доводить до конца: задача из нескольких шагов (например, «закоммить и сделать 7.1») выполняется вся, по порядку, в том же ходе — сначала коммит, потом следующий шаг. Не переходить к следующему шагу, пока предыдущий не доведён (файлы записаны, коммит сделан, тесты прогнаны, журнал обновлён). Если шаг требует подтверждения — спросить один раз и по ответу сразу сделать.

## Как разбивать новые планы

Образец — этап 9 в `docs/GPU-BACKEND.md`.

1. **Разбивка до атомарного уровня.** Задача из плана → подзадачи → дальше, пока шаг не станет одним проверяемым изменением. Нумерация иерархическая: `9.4.3`, `9.3.2.1`. Подпункты, которые зависят от результата разведки, дописываются после неё («до этого этап не начинается»).
2. **У каждого шага, включая атомарные, есть контрольная точка (КТ).** Формат: `КТ (авто): что и чем проверяется` — тест, сравнение с эталоном (хэш картинки, паритет, `cmp` скриншотов), замер с числовой целью; `КТ (ручная): …` — если нужен пользователь (окно, телефон).
3. **Разведка раньше переделки.** Первый шаг этапа — дешёвая проверка, нужно ли остальное (оценка на CPU, замер окна перекрытия, профиль). Если цель не стоит риска — этап снимается или закрывается разведкой, с записью в журнал.
4. **План фиксируется в `docs/` до начала работы**; у шага стоит чекбокс `[ ]`, закрытие — `[x]` и запись результата КТ в журнал (числа до/после, что не достигнуто и почему, а не только что сделано).
5. **Порядок:** сначала шаги, проверяемые автономно; шаги с участием пользователя помечены явно и идут в конце.
6. **Риск за флагом.** Рискованные переделки включаются переменной окружения (`SUNPETAL_TILED=1`), проходят паритет и слепой прогон 30 000 кадров, потом становятся умолчанием с переключателем обратно; старый путь удаляется отдельным коммитом после срока без регрессий.
7. **Временную инструментацию** (счётчики, хэши кадров) не коммитить: хранить патчем в scratchpad, итог — таблицей в журнале.
8. **Обновлять этот файл** (раздел «Состояние») при закрытии этапа или шага плана.
