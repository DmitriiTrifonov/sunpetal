# Чёткая 2D-графика интерфейса (этап 8е), записано 2026-11-01

Просьба автора: пункты меню устройства Катарины (и похожий интерфейс) нарисованы графикой DS низкого разрешения; в PS2-версии таких пунктов нет, взять оттуда нечего. Нужно либо перерисовать, либо грамотно заапскейлить картинки: улучшение, которого нет и в PS2.

## Разведка (2026-11-01, нижний экран в меню устройства, `sunpetal-debug`, русский пакет)

- Нижний экран (движок B): `DISPCNT` = `C0213210`, включены **BG1** и **объекты (спрайты)**; `BG1CNT` = `2107` (текстовый фон, 16 цветов, 32×32 клетки). Иконки пунктов (ЗАМЕТКИ, ЗАПИСЬ, ВЕЩИ; в английском: GUIDE BOOK, MEMO, SAVE, GOODS), рамка выбора и осциллограмма — тайлы BG1; спрайтов в этом экране всего 2 (стрелка возврата 32×16 + 32×8 справа внизу, `x 220, y 170`), остальные записи OAM спрятаны или за краем.
- Верхний экран (циферблат, полоса кнопок) — тоже 2D (рамка и надписи «ВЫБОР», «ЖМИ» — графика пакета перевода).
- Пакеты текстур (`texpack`, этап 7) подменяют **только 3D**; 2D они не трогают (`docs/STATUS.md`: «не трогает 2D»). Значит, механизма подмены 2D-картинок сейчас нет.
- Надписи пунктов (ЗАМЕТКИ, ЗАПИСЬ, ВЕЩИ) уже нарисованы в пакете перевода (`fsar-ru`, гнёзда графики), поэтому заменяемая картинка зависит от языка: ключ подмены включает данные тайлов, а у русской версии они свои.
- PS2: схема устройства («Dial», «Juck», «Guide Book»), крупная страница справочника и панель с номерами (`docs/RECON-SCREENS.md`); пунктов MEMO, SAVE, GOODS и иконок чемодана нет. Брать оттуда только стиль (цвета, рамка), не картинки.

**8е.2 (2026-11-01):** `nds::dump_2d(DIR)` (`gpu2d.rs`), `sunpetal-headless --dump-2d DIR` (на кадрах `--shots`/`--shot-every`), команда REPL `dump2d DIR` в `sunpetal-debug`. Каждый кадр на первой строке (`collect_replaced`) собираются спрайты, чей ключ есть в пакете (обычный: без поворота, не полупрозрачный, не окно, не битовый); движок их не рисует, картинку кладёт поверх готового кадра `overlay_pack` в разрешении окна (`screens_pixels`, билинейно, с альфой, отражение по битам OAM). Тест `a_2d_pack_replaces_the_sprites_it_names_and_nothing_else`: пустой пакет = без пакета; пакет из выгрузки кадра даёт тот же кадр пиксель в пиксель; пакет из однотонных картинок меняет только прямоугольники названных спрайтов. **Ограничения:** (1) картинка ложится поверх всего кадра, приоритеты фонов и других спрайтов не учитываются; (2) пока у движка включён блендинг на объекты или затемнение (`BLDCNT`, `MASTER_BRIGHT`), спрайты рисует сам движок (переходы, логотипы) — иначе пропал бы эффект; (3) только спрайты: фоновые слои (ключ — хеш пикселей слоя) и широкий верхний экран (`upper_wide_rgba`) пакет пока не трогает; (4) пакет — папка, а не часть `sunpetal.data` (8е.5). `video_reset` сохраняет пакет.

**8е.2, остаток (2026-11-01):** добраны сцены устройства Катарины (верх: циферблат, низ: осциллограф), экран пунктов чемодана, MEMO, SAVE (экран Эдо «Hello!! SAVE DATA»), GOODS («Character Profiles»): 92 файла в одной выгрузке `artifacts/2d-dump-d` (не в git). Теперь по всем 18 строкам таблицы 8е.1 есть выгрузка (строки 1–18); КТ 8е.2 выполнена. Маршрут (см. также скилл `screen-recon`): после `--goto C02_01 --autoplay`, `skip 100`: `press START 3`, `tap 25 43 4`, `advance 100` — устройство; `press RIGHT 3` — нижний экран с четырьмя пунктами; `tap X 85 4` с X = 50 (GUIDE BOOK), 100 (MEMO), 150 (SAVE), 203 (GOODS), потом `advance 150`; стрелка внизу справа (`tap 236 178`) открывает панель Back/Delete/Change/Exit, «Exit» выходит из устройства совсем. **8е.3, фоновые слои (2026-11-01):** файлы `bg{движок}{слой}_{хеш}.png` из выгрузки теперь тоже подменяют: на первой строке кадра `bg_layers` собирает слои как в выгрузке и считает хеш пикселей; если картинка с таким хешем есть в пакете, `overlay_pack` кладёт её (любого размера, билинейно) на те пиксели, где сверху в кадре как раз этот слой (`Gpu2d::top` — слой сверху для каждого пикселя, пишется на каждой строке); спрайты и другие слои поверх остаются как рисует движок, поэтому приоритеты соблюдаются. Тест `a_2d_pack_replaces_background_layers`: пакет из слоёв кадра даёт тот же кадр пиксель в пиксель; пакет из однотонных слоёв красит только пиксели этого цвета, остальное не меняет. Ограничения: ключ слоя включает прокрутку, поэтому прокручиваемые слои дают новый ключ на каждом положении (интерфейс стоит на месте, годится); слой, видимый кусками, подменяется только в видимых пикселях по границам DS-пикселя (край картинки не выходит за силуэт); при блендинге и затемнении движка подмены нет; верхний широкий экран не затронут.

Качество по трём образцам не измерялось: образцы делает 8е.4б; оценки ниже — по описаниям источников и по свойствам наших картинок (16 цветов, прозрачность, мелкие размеры). ### Рекомендация

**Порядок источников (решение автора, 2026-11-01):** если у картинки есть аналог на PS2 диске (текстуры, 2D-фоны этапа 7, титул, страницы справочника), берётся он; апскейл и перерисовка нужны только тем картинкам, которых у PS2 нет (по таблице 8е.1: пункты MEMO, SAVE, GOODS, иконки чемодана и стрелка возврата, счётчик, рамка выбора — на PS2 их нет, там схема «Dial / Juck / Guide Book» и страница справочника). Поэтому образцы 8е.4б сделаны на иконках устройства, а Real-ESRGAN из пункта 2 ниже нужен лишь для полноэкранных DS-картинок без пары на PS2; сколько их, выяснится по шагу «2D-фоны PS2» (этап 7).

Смешанный способ (вариант (в) шага 8е.4), по типу картинки, чтобы не тащить один метод на всё:

1. **Мелкие значки и стрелка** (OBJ 16×16…64×32; чемодан, возврат, счётчик): сначала Scale2x/EPX и xBR-подобный (свой код) ×4 как базовый вариант, затем VTracer на плоских значках для проверки «векторного» вида. Оба дёшевы, детерминированы и на образцах 8е.4б сравниваются за вечер; ML для них не брать (домысливание на 16 цветах).
2. **Полноэкранные картинки** (титул, страницы справочника, фоны меню): Real-ESRGAN (anime, ncnn), один раз при сборке пакета, результат хранится в `sunpetal.data` (часть 2DPK), дальше без нейросети. Альфа и края обрабатываются отдельно.
3. **Надписи**: шрифтом (8д), не апскейлом; надписи в графике перевода — как в 8д.
4. **Ключевые элементы** (4 пункта чемодана, рамка, курсор) — кандидаты на ручную перерисовку, если автор захочет лучше апскейла; решает 8е.4в по образцам.

Лицензионно: пакет собирает сам пользователь из своего ROM (как текстуры PS2), готовые увеличенные картинки игры в репозиторий и в дистрибутив не идут; поэтому важны лицензии инструментов (Real-ESRGAN BSD-3, VTracer MIT — подходят; Potrace GPL и неизвестные веса — нет), а не авторство картинок.

Что дальше: 8е.4б делает образцы (3 иконки и стрелка в пунктах 1 и 2: Scale2x, xBR-подобный, VTracer, Real-ESRGAN) — для этого нужен установленный `realesrgan-ncnn-vulkan` или `realesrgan-ncnn-py` (не ставился, ставить только по слову автора, это внешняя загрузка), а остальные методы пишутся на Python без внешних библиотек.

## Согласование 8е с 8б, 8д и 9 (8е.6, 2026-11-01)

**8б (раскладки, врезки):** подмена лежит в `screens_pixels` (оба экрана одной картинкой в разрешении `res`), а раскладки (`single`, врезка головоломок, угловая кнопка) режут ту же картинку, поэтому подменённые картинки попадают на те же прямоугольники без правок раскладок. Не затронут широкий верхний экран (`upper_wide_rgb_layers`): в широком режиме 2D верхнего экрана остаётся прежним (на верхнем экране со сценой это панели реплик и рамки, их заменяет 8д и 3D-путь). Приложение разбирает готовую картинку (`dialogue_shown`, `portrait_left`, `dialogue_panel_middle`, `edge_color`, `prompt_box`, правило выбора экрана): подменённые картинки должны сохранять ключевые цвета (синяя плашка «PRESS START», красная линия реплики, белый/зелёный фон логотипов), иначе правила собьются; это условие для авторов пакета (8е.4–8е.5), проверка — прогон `the_rule_picks_the_screen_on_the_recorded_screens` с пакетом.

**8д (текст):** надписи пунктов (ЗАМЕТКИ, ЗАПИСЬ, ВЕЩИ), реплики и подсказки в этот пакет не идут: реплики рисует egui (`hide_dialogue_raster`), графические надписи пакета перевода перерисовываются шрифтом при составлении 2D-пакета, а не апскейлятся. Слой BG3 верхнего экрана в полосе 144–191 (текст реплик) в 2D-пакет не брать.

**9 (язык):** ключ картинки — хеш данных, а в русской версии данные графики другие (гнёзда пакета перевода), поэтому у каждого языка свой набор файлов; пакет собирается для пары «ROM + язык» и называется по ней. Подмена не меняет логику языка: без пакета и в других языках кадр прежний. Одинаковые картинки у разных языков (значки, рамки) вынести в общую часть пакета.

**8е.5, часть `sunpetal.data` (2026-11-01):** секция `2DPK` (формат `P2D1`: имя и PNG на картинку, `sunpetal-data::pack2d`), инструмент `sunpetal-pack-2d --dir ПАПКА --out FILE [--merge sunpetal.data]` (с `--merge` остальные части сохраняются, `2DPK` заменяется; `sunpetal-check` называет её «2D pictures» и проверяет CRC). Рантайм читает пакет из папки или из файла (`Pack2d::load`), приложение берёт `2DPK` из используемого файла данных само (или из `SUNPETAL_PACK_2D=папка|файл`). Тест: картинки из части файла рисуют тот же кадр, что из папки (`a_2d_pack_replaces_the_sprites_it_names_and_nothing_else`). **Остаётся:** сами картинки для чемодана и остального интерфейса (нужен выбор 8е.4в), ручной снимок окна до и после.
