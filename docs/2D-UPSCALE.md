## Разведка (2026-11-01, нижний экран в меню устройства, `sunpetal-debug`, русский пакет)

- Нижний экран (движок B): `DISPCNT` = `C0213210`, включены **BG1** и **объекты (спрайты)**; `BG1CNT` = `2107` (текстовый фон, 16 цветов, 32×32 клетки). Иконки пунктов (ЗАМЕТКИ, ЗАПИСЬ, ВЕЩИ; в английском: GUIDE BOOK, MEMO, SAVE, GOODS), рамка выбора и осциллограмма — тайлы BG1; спрайтов в этом экране всего 2 (стрелка возврата 32×16 + 32×8 справа внизу, `x 220, y 170`), остальные записи OAM спрятаны или за краем.
- Верхний экран (циферблат, полоса кнопок) — тоже 2D (рамка и надписи «ВЫБОР», «ЖМИ» — графика пакета перевода).
- Пакеты текстур (`texpack`, этап 7) подменяют **только 3D**; 2D они не трогают (`docs/STATUS.md`: «не трогает 2D»). Значит, механизма подмены 2D-картинок сейчас нет.
- Надписи пунктов (ЗАМЕТКИ, ЗАПИСЬ, ВЕЩИ) уже нарисованы в пакете перевода (`fsar-ru`, гнёзда графики), поэтому заменяемая картинка зависит от языка: ключ подмены включает данные тайлов, а у русской версии они свои.
- PS2: схема устройства («Dial», «Juck», «Guide Book»), крупная страница справочника и панель с номерами (`docs/RECON-SCREENS.md`); пунктов MEMO, SAVE, GOODS и иконок чемодана нет. Брать оттуда только стиль (цвета, рамка), не картинки.

## Журнал

**8е.2 (2026-11-01):** `nds::dump_2d(DIR)` (`gpu2d.rs`), `sunpetal-headless --dump-2d DIR` (на кадрах `--shots`/`--shot-every`), команда REPL `dump2d DIR` в `sunpetal-debug`. Пишет слои фона обоих движков (`bg{движок}{слой}_{хеш пикселей}.png`, 256×192) и каждый видимый спрайт таким, как лежит в памяти объектов, без отражения и поворота: `obj{движок}_{w}x{h}_{хеш тайлов}_{хеш используемой палитры}.png`; `index.csv` (kind, engine, layer_or_oam, x, y, w, h, key, file) дописывается к прежнему и сортируется, поэтому повторный прогон даёт те же файлы. Ключ мелкой картинки — хеш байтов тайлов и хеш используемых цветов палитры (как у 3D-текстуры); ключ слоя фона — хеш его пикселей (ключ по клеткам карты и тайлам остаётся на 8е.3). Тест `the_2d_dump_is_the_same_on_every_run` (два прогона 1600 кадров: те же имена файлов и тот же индекс). На маршруте `C02_01` → меню → чемодан → справочник: 4 выгрузки, 43 PNG (спрайты 32×16, 8×16, 8×32 и др., 8 слоёв фона), повтор — побайтно тот же список и `index.csv` (48 строк). **Не сделано:** прогон по всем 18 строкам таблицы (титул, логотипы, Эдо, предметы GOODS, сохранение дошли не все), нужен для закрытия КТ.

**8е.2, прогон по сценам (2026-11-01):** без сохранения, `sunpetal-debug --repl`: 20 × `advance 150` (логотипы, ролик, титул) + `press START` + касание Request — 22 вызова `dump2d`, 75 файлов (12 слоёв фона, остальное спрайты: 64×32 и 64×64 — надписи и логотип титула, 32×16/32×32 — кнопки, 8×8…16×32 — мелочь). Папка PNG с именами, как у `dump_2d` (`obj{движок}_{w}x{h}_{данные}_{палитра}.png`, движок в ключ не входит; картинка любого размера, обычно оригинал × целое). Каждый кадр на первой строке (`collect_replaced`) собираются спрайты, чей ключ есть в пакете (обычный: без поворота, не полупрозрачный, не окно, не битовый); движок их не рисует, картинку кладёт поверх готового кадра `overlay_pack` в разрешении окна (`screens_pixels`, билинейно, с альфой, отражение по битам OAM). Тест `a_2d_pack_replaces_the_sprites_it_names_and_nothing_else`: пустой пакет = без пакета; пакет из выгрузки кадра даёт тот же кадр пиксель в пиксель; пакет из однотонных картинок меняет только прямоугольники названных спрайтов. **Ограничения:** (1) картинка ложится поверх всего кадра, приоритеты фонов и других спрайтов не учитываются; (2) пока у движка включён блендинг на объекты или затемнение (`BLDCNT`, `MASTER_BRIGHT`), спрайты рисует сам движок (переходы, логотипы) — иначе пропал бы эффект; (3) только спрайты: фоновые слои (ключ — хеш пикселей слоя) и широкий верхний экран (`upper_wide_rgba`) пакет пока не трогает; (4) пакет — папка, а не часть `sunpetal.data` (8е.5). `video_reset` сохраняет пакет.

Тест `a_2d_pack_replaces_background_layers`: пакет из слоёв кадра даёт тот же кадр пиксель в пиксель; пакет из однотонных слоёв красит только пиксели этого цвета, остальное не меняет. Ограничения: ключ слоя включает прокрутку, поэтому прокручиваемые слои дают новый ключ на каждом положении (интерфейс стоит на месте, годится); слой, видимый кусками, подменяется только в видимых пикселях по границам DS-пикселя (край картинки не выходит за силуэт); при блендинге и затемнении движка подмены нет; верхний широкий экран не затронут.

1. **Мелкие значки и стрелка** (OBJ 16×16…64×32; чемодан, возврат, счётчик): сначала Scale2x/EPX и xBR-подобный (свой код) ×4 как базовый вариант, затем VTracer на плоских значках для проверки «векторного» вида. Оба дёшевы, детерминированы и на образцах 8е.4б сравниваются за вечер; ML для них не брать (домысливание на 16 цветах).
2. **Полноэкранные картинки** (титул, страницы справочника, фоны меню): Real-ESRGAN (anime, ncnn), один раз при сборке пакета, результат хранится в `sunpetal.data` (часть 2DPK), дальше без нейросети. Альфа и края обрабатываются отдельно.
3. **Надписи**: шрифтом (8д), не апскейлом; надписи в графике перевода — как в 8д.
4. **Ключевые элементы** (4 пункта чемодана, рамка, курсор) — кандидаты на ручную перерисовку, если автор захочет лучше апскейла; решает 8е.4в по образцам.

Лицензионно: пакет собирает сам пользователь из своего ROM (как текстуры PS2), готовые увеличенные картинки игры в репозиторий и в дистрибутив не идут; поэтому важны лицензии инструментов (Real-ESRGAN BSD-3, VTracer MIT — подходят; Potrace GPL и неизвестные веса — нет), а не авторство картинок.

Что дальше: 8е.4б делает образцы (3 иконки и стрелка в пунктах 1 и 2: Scale2x, xBR-подобный, VTracer, Real-ESRGAN) — для этого нужен установленный `realesrgan-ncnn-vulkan` или `realesrgan-ncnn-py` (не ставился, ставить только по слову автора, это внешняя загрузка), а остальные методы пишутся на Python без внешних библиотек.

## Согласование 8е с 8б, 8д и 9 (8е.6, 2026-11-01)

**8б (раскладки, врезки):** подмена лежит в `screens_pixels` (оба экрана одной картинкой в разрешении `res`), а раскладки (`single`, врезка головоломок, угловая кнопка) режут ту же картинку, поэтому подменённые картинки попадают на те же прямоугольники без правок раскладок. Не затронут широкий верхний экран (`upper_wide_rgb_layers`): в широком режиме 2D верхнего экрана остаётся прежним (на верхнем экране со сценой это панели реплик и рамки, их заменяет 8д и 3D-путь). Приложение разбирает готовую картинку (`dialogue_shown`, `portrait_left`, `dialogue_panel_middle`, `edge_color`, `prompt_box`, правило выбора экрана): подменённые картинки должны сохранять ключевые цвета (синяя плашка «PRESS START», красная линия реплики, белый/зелёный фон логотипов), иначе правила собьются; это условие для авторов пакета (8е.4–8е.5), проверка — прогон `the_rule_picks_the_screen_on_the_recorded_screens` с пакетом.

**8д (текст):** надписи пунктов (ЗАМЕТКИ, ЗАПИСЬ, ВЕЩИ), реплики и подсказки в этот пакет не идут: реплики рисует egui (`hide_dialogue_raster`), графические надписи пакета перевода перерисовываются шрифтом при составлении 2D-пакета, а не апскейлятся. Слой BG3 верхнего экрана в полосе 144–191 (текст реплик) в 2D-пакет не брать.

**9 (язык):** ключ картинки — хеш данных, а в русской версии данные графики другие (гнёзда пакета перевода), поэтому у каждого языка свой набор файлов; пакет собирается для пары «ROM + язык» и называется по ней. Подмена не меняет логику языка: без пакета и в других языках кадр прежний. Одинаковые картинки у разных языков (значки, рамки) вынести в общую часть пакета.

**8е.5, часть `sunpetal.data` (2026-11-01):** секция `2DPK` (формат `P2D1`: имя и PNG на картинку, `sunpetal-data::pack2d`), инструмент `sunpetal-pack-2d --dir ПАПКА --out FILE [--merge sunpetal.data]` (с `--merge` остальные части сохраняются, `2DPK` заменяется; `sunpetal-check` называет её «2D pictures» и проверяет CRC). Рантайм читает пакет из папки или из файла (`Pack2d::load`), приложение берёт `2DPK` из используемого файла данных само (или из `SUNPETAL_PACK_2D=папка|файл`). Тест: картинки из части файла рисуют тот же кадр, что из папки (`a_2d_pack_replaces_the_sprites_it_names_and_nothing_else`). **Остаётся:** сами картинки для чемодана и остального интерфейса (нужен выбор 8е.4в), ручной снимок окна до и после.

### Модели чемодана на PS2 (8е.7а2, 2026-11-01)

Модели чемодана на PS2 нет. ### Значки кнопок и апскейл PS2-картинок (8е.7в, 2026-11-01)

**Значки кнопок.** Читаемые PS2-глифы лежат в схеме Juck, `016_034`–`016_066` (64×23, пары «значок и пустая рамка», зелёная и розовая рамка) и `016_050` (широкая кнопка); в рендере кейса значки на полосе кнопок золотые кружки по ~6 px и не читаются. **Апскейл.** `tools/ps2/case_up.py` (около 6 минут, почти всё время Upscayl) увеличивает рендеры кейса 352×420, схему KATHARINE, цифры, лампу, PUSH методами `lanczos-sharp`, `catrom`, `adaptive`, `lanczos-median` и Upscayl (`/Applications/Upscayl.app`, уже стоял у автора) в ×2/×3/×4: `build/ps2-case/up/<картинка>/<метод>_x{2,3,4}.png`, листы в `sheets/` (`case_x3_vs_ds.png`: кейс ×3 рядом с DS). **Итог:** на рендере кейса и диске заметно лучше ML (Upscayl ×4: чистые края, ровная фаска, рубчатая ручка), методы ImageMagick дают мягкую картинку со ступеньками; для цифр, лампы и PUSH достаточно `lanczos-sharp`. ML на мелких деталях дорисовывает форму: ряд цифр на диске, «SELECT», «KATHARINE» и значки на полосе кнопок исходно размыты, их перерисовывать шрифтом и по гайду. Плоского вида нет: перспектива рендера остаётся.

## Id картинок и манифест `pack.toml` (K-092)

Хеш остаётся ключом совпадения; id — имя поверх него. В папке 2D-пакета может лежать `pack.toml`:

```toml
[push]                       # id; картинка — push.png
keys = ["obj0_16x32_{data}_{pal}"]
ru = ["obj0_16x32_{data2}_{pal2}"]   # любое имя списка (keys, en, ru…): все ключи работают
```

- Ключ — имя выгрузки без `.png`, можно с `@группа.вариант`; id — имя без `.` и `/`.
- Файл, названный по ключу, главнее манифеста; без манифеста всё работает как раньше. Id без `{id}.png` — ошибка загрузки.
- Одна картинка на несколько ключей (палитры, языки, ЖМИ/PUSH).
- Загрузка: `sunpetal_data::pack2d::{parse_manifest, manifest_pictures}`; упаковка в `sunpetal.data` разворачивает манифест в картинки по ключам (рантайму манифест в данных не нужен).
- Инструмент: `tools/ps2/packid.py fold DIR [IDS.csv]` — файлы-по-ключам → `{id}.png` + `pack.toml` (одинаковое содержимое сливается; id из `IDS.csv` или `p_<sha1>`); `packid.py index DUMP PACK` — колонка `id` в `index.csv` выгрузки. Тесты: `tools/ps2/test_packid.py`.
- Проверено на копии `build/2d-pack-case`: 112 ключей → 112 id, набор ключей совпал. Осмысленные id (`case.push`…) задаёт `IDS.csv` в следующих задачах 8е.1 (K-118…K-123).

Для Act Imagine («video codec») трассировка по `upscayl` рвёт тонкий текст, оставлен чистый `upscayl`. Marvelous: «t» кривые уже в оригинале 256×192, в обоих вариантах. Из сети: Rising Star Games — готовый PNG (выше); h.a.n.d. — на Wikimedia Commons другая версия знака (с японской подписью, без свечения), не подходит; кадры Grasshopper на avid.wiki — те же гербы, но 960×720 с видео, не лучше нашего.
