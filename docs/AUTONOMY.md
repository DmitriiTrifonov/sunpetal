# Автономия агентов и время автора (2026-11-11)

Задача автора: «я один, мне тяжело всё проверять; агент не может сам ходить по игре — ни в `sunpetal`, ни в `sunpetal-ee`, ни в PCSX2». Здесь: что уже есть, где дыры, порядок работы, при котором автор тратит минуты, и шаги по инструментам (этап «А»).

## 1. Что есть сейчас

| Среда | Что агент умеет сам | Чего не умеет |
|---|---|---|
| `sunpetal`, машина без окна (`sunpetal-debug --repl`) | `goto Cnn_yy`, `request`, `teleport`, `changemap`, `walk`, `press`, `tap`, `drag`, `skip`, `advance`, `shot`, `state`, `peek/poke`, трассы вызовов, `dump2d` | каждый запуск идёт с загрузки игры; снимка состояния нет; нужен особый сейв (`build/full100.sav`); `shotwide` не работает |
| `sunpetal`, картинка окна без окна (`sunpetal-app --script`, K-090) | раскладки, чёткий текст, эффекты, меню: `wait`, `until dialogue\|idle`, `press`, `tap`, `set KEY VALUE`, `shot`, `status` | нет `teleport/walk` (только `--goto` на старте); звук не проверяется |
| `sunpetal`, повтор ввода (K-124, `sunpetal-headless --input --shots`) | детерминированный прогон записи автора, ~1200 кадров/с | запись привязана к конкретной сборке данных: смена пакета может сдвинуть кадры |
| `sunpetal-ee`, рекомп PS2 | пакетный прогон по переменным: `PS2_PAD` (ввод по кадрам), `PS2_POKE` (запуск любой сцены через «Request»), `PS2_CALL` (вызвать событие), `PS2_TRACE/PROF`, кадр → PNG своим рендером GS | нет диалогового режима: любой вопрос = новый прогон с нуля; нет «листать реплики до…»; нет снимка состояния; нет свободной камеры |
| PCSX2 (`fsar-ru/scripts/pcsx2_ctl.py`, PINE) | чтение и запись памяти, сохранение и загрузка состояний, снимок по F8 | **ввод требует активного окна и отбирает клавиатуру** → только когда автора нет за компьютером; снимок 3–8 с; меню проходится ненадёжно; на карте памяти автора открыто только до R-06 |

Где сейчас уходит время автора (по канбану): 5 карточек стоят в «Проверке», 14 незакрытых требуют ручной проверки, в `docs/qa` 10 ТЗ, из них 5 «нужно окно». Самые дорогие по часам карточки (`timelog.csv`) — те, где работа шла вместе с автором: K-124 (46 ч), K-076 (21 ч).

Вывод: в `sunpetal` инструменты в основном есть, не хватает **постоянного сеанса, закладок и упаковки проверок**. В рекомпе PS2 не хватает **диалогового режима**. PCSX2 нужно **перестать водить клавишами**.

## 2. Порядок работы

### 2.1. Лестница проверки

Каждая контрольная точка поднимается на ступень выше только тогда, когда нижняя невозможна. В планах КТ получает третий вид.

1. **КТ (авто)** — тест, хэш, метрика. Как сейчас.
2. **КТ (глаза агента)** — новый вид. Агент сам снимает кадр (`shot`), смотрит его и пишет, что видит, приложив путь. Годится для «объект на месте», «текст не обрезан», «нет мусора в кадре». Обязательна пара «до/после» или «DS/PS2».
3. **КТ (автор, по картинке)** — автор отвечает «да/нет/вариант Б» по готовой странице, **не запуская игру**. Для вкуса и выбора.
4. **КТ (автор, в игре)** — только то, что по картинке не решить: отклик управления, звук на слух, плавность, телефон.

Правило для агента: ступень 4 без попытки 1–3 ставить нельзя; в карточке пишется, почему ниже не получилось.

### 2.2. Пакет на проверку (вместо россыпи ТЗ)

- Агент не ждёт автора. Довёл до ручной КТ — карточка в «Проверку», вопрос — в пакет, сам берёт следующую по очереди.
- Пакет — одна локальная страница `artifacts/review/ГГГГ-ММ-ДД/index.html` (ассеты игры наружу не уходят). Один пункт = один вопрос с ответом в один щелчок: «да / нет / пропустить» или «А / Б». К пункту приложено всё, чтобы ответить без игры: кадры до и после рядом, для движения — ролик 5–10 с.
- Не больше 10 пунктов в пакете, расчёт — 10 минут. Пункты ступени 4 собраны в конце и идут **туром** (2.3).
- Ответы пишутся в `artifacts/review/ГГГГ-ММ-ДД/answers.json`. Агент разбирает: «да» → `close-qa`; «нет» → `bug-task` с тем же кадром; «пропустить» → в следующий пакет.
- `docs/qa/K-NNN.md` остаются только для ступени 4, где нужен порядок действий руками.

### 2.3. Тур проверки (ступень 4 без беготни)

Автор запускает одну команду. Игра сама по очереди переносит его в нужные места (закладки, 2.4) с нужными настройками, показывает подпись «что проверить». Автор смотрит, пробует управление и жмёт «годится» или «не годится» (при «не годится» сохраняются кадр, состояние и последние 10 с записи — механизм K-097). Автор не ищет место, не вспоминает, что проверять, и ничего не пишет.

### 2.4. Закладки: 5 секунд автора вместо часов агента

Место, куда агент не дошёл сам, автор отмечает один раз клавишей в живой игре: сохраняется запись ввода от старта, сейв, номер кадра, сцена, имя. Дальше агент возвращается туда сколько угодно раз без автора. Все закладки и все известные маршруты лежат в одном **каталоге мест** с единым именем для трёх сред: «парковка, вид на ворота» = как попасть в DS, в рекомпе PS2 и в PCSX2.

### 2.5. Что остаётся автору

- Решения вкуса по парам картинок (ступень 3).
- Тур раз в день или реже (ступень 4).
- Закладки там, где агент застрял (он просит одной фразой: «нужна закладка: глава 7, диалог у бара»).
- Допуски и приоритеты.

Всё остальное — не его работа. Если агент просит автора что-то «посмотреть в игре» вне пакета — это нарушение порядка.

### 2.6. PCSX2 — арбитр, а не рабочая среда

Рекомп PS2 уже воспроизводит игру и сверен с PCSX2 по кадру. Поэтому ходим по PS2-версии в рекомпе, а PCSX2 запускаем редко: снять эталон и разрешить спор. Тогда его неудобство (фокус, клавиатура) почти не мешает.

## 6. Риски

| Риск | Что делаем |
|---|---|
| Агент на ступени «глаза» выдаёт желаемое за увиденное | пара «до/после» обязательна; в золотых кадрах решает хэш, не описание; спорное уходит автору по картинке |
| Записи ввода ломаются при смене данных | якоря по событиям (А2.8) |
| Снимок состояния у рекомпов недостижим (стеки сгенерированного кода, потоки) | кэш маршрутов: игра детерминирована и быстра |
| Ввод в PCSX2 без фокуса не получится | PCSX2 только арбитр; места — состояниями, сцены — записью в память |
| Пакеты копятся быстрее, чем автор отвечает | лимит 10 пунктов; агент сам сортирует по важности; «пропустить» не блокирует работу |
