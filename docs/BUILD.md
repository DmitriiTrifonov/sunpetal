# Сборка из своего ROM

Sunpetal не содержит игры. Игровой код получается из **вашего собственного дампа** картриджа: рекомпилятор превращает его в C, который собирается вместе с рантаймом. Поэтому готовых сборок с игрой нет и не будет: сгенерированный код является производным от ROM. В репозитории только инструменты (`tools/`), рантайм и приложение (`crates/`).

## Какой ROM нужен

Европейская версия Nintendo DS, код игры `YHNP` (языки En, Fr, De, Es, It), дамп без изменений:

- SHA-1 `4922df257dd3289114895ad734808917e60b2541`, 64 МиБ;
- код ARM9 с CRC-32 `c7c5fdb6` (его определяет рекомпилятор).

Образы других регионов и версий не подойдут: код отличается. Образы с переводом, которые меняют только данные и раскладку файлов (код ARM9 тот же), работают: проверено на русской сборке из проекта перевода (SHA-1 другой, размер не степень двойки).

Как получить дамп, спросите своё устройство: свой картридж снимают на самой консоли (программами для DS/DSi/3DS) в файл `.nds`. Ссылки на готовые образы проект не даёт.

## Что нужно

- Rust (rustup, свежий стабильный; проверено на 1.99).
- Python 3.9+ (для рекомпилятора, зависимостей нет).
- Компилятор C, понимающий `gnu11` (clang или gcc; для Windows подойдут clang или MinGW, MSVC не подходит).
- Linux: пакеты `libasound2-dev`, `libudev-dev` (звук и геймпады).

## Рекомпиляция и сборка (macOS, Linux, Windows)

```sh
ROM=/путь/к/игре.nds
export PYTHONPATH=$PWD/tools
python3 -m ndskit.recomp "$ROM" --out generated/recomp          # ~45 с, получается C
cargo build --release -p sunpetal-app                            # первая сборка несколько минут
./target/release/sunpetal-app "$ROM"
```

Каталог `generated/` в `.gitignore`: сгенерированный код в репозиторий не попадает. Без него `cargo build` всё равно проходит (собирается рантайм без модулей игры), так работает CI.

Проверка рекомпилятора (по желанию): `--optest` и `python3 -m ndskit.recomp.selftest`, см. `AGENTS.md`.

## Файл данных (лучшие текстуры из PS2-версии)

Игрок может собрать из своих образов один файл `.spdata` с улучшенными ресурсами; приложение берёт его вместо оригинальных текстур DS там, где у файла есть замена (путь в меню: Графика → «Файл данных или папка текстур», или `--texture-pack`, или `video.texture_pack` в `config.toml`). Файл собирается на своей машине и никому не передаётся: он производный от ваших образов.

Одной командой из DS-ROM и PS2-диска:

```sh
python3 tools/build-data.py "$ROM" диск.iso game.spdata --cache build/ps2.cache
```

Что происходит: `tools/ds/nitro.py` читает из файлов DS-ROM все модели и архивы текстур (`.nsbmd`, `.nsbtx`, в том числе сжатые) и для каждой текстуры считает тот же ключ, что и рантайм; каждая текстура сопоставляется с картинками диска (в PS2-версии они больше) сначала по уменьшенной копии, потом точно в размере DS (средняя ошибка цвета, ошибка по блокам, различие контуров). Подошедшие пары записываются в файл. Первый запуск строит индекс диска (около 15 минут, ~15 000 картинок; `--cache` сохраняет), сама сборка около 2 минут. Рядом ложится `game-report.csv` со всеми текстурами и мерами совпадения.

Результат на нашей паре образов (японский PS2-диск и европейское DS-ROM): 739 из 1649 текстур (45 %) нашли пару, в файле 1426 ключей, около 5 МБ. Остальные: у DS нет парной картинки на диске (другие ассеты) или раскладка отличается. Пороги можно менять (`--max-mae`, `--max-block`, `--max-edges`); просмотр пар показал, что при контурной мере до 0,62 совпадения почти все верные, выше 0,7 часто неверные.

Текстуры, которые игра меняет в памяти уже после загрузки (лица персонажей и их палитры), по одним файлам не посчитать: для них `--dump DIR` берёт выгрузку, снятую самой игрой (`sunpetal-headless --dump-textures DIR`, проиграйте нужные места). Там, где палитра в игре отличается от записанной в файле, работает запись «любая палитра»: картинка для текстуры с данными из ROM подходит при любой палитре, если точного ключа нет.

Модели из PS2 (шаг C) лягут в тот же файл отдельной секцией `MODL`; формат описан в `tools/ps2/spdata.py`.

## Управление

Стрелки, Z/X/S/A (кнопки A/B/X/Y), Q/W (L/R), Enter (Start), Backspace (Select); мышь по нижнему экрану это стилус. F1 или Esc открывает меню (графика, эффекты, звук, управление, профили), F2 раскладка, F3 фильтр, F4/F5 разрешение 3D, F6 эффекты, F11 полный экран, Tab ускорение. Геймпад поддерживается. Настройки в `config.toml` папки конфигурации (macOS: `~/Library/Application Support/sunpetal`, Linux: `~/.config/sunpetal`).

## Android

См. [ANDROID.md](ANDROID.md): `tools/android/build-apk.sh` собирает `apk` (нужны Android SDK, NDK r27, `cargo-ndk`), ROM выбирается на телефоне при первом запуске. Рекомпиляция (см. выше) должна быть сделана до сборки: `apk` содержит сгенерированный код, поэтому выкладывать его нельзя.

## Вопросы

- **Игра запускается и сразу «зависает» на очень малой скорости.** Проверьте, что ROM из списка выше. На неподходящем ROM рекомпилированный код читает не те данные.
- **Нет звука.** Проверьте громкость в меню; без звукового устройства приложение работает без звука.
- **Где сохранения?** Рядом с ROM (`имя.sav`) или в папке, заданной `--out`; на Android в `Android/data/org.sunpetal.app/files/`.
