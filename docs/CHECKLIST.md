# Чек-лист поведения DS-версии

Источник: гайд «FSR Version Differences» (speedrun.com, AdrianVG, сравнение PS2 JP и DS). Пункты про DS проверяем в приложении руками; отметка `[x]` значит «совпадает с оригиналом».

## Титул и меню

- [x] Логотипы → вступительный ролик → Press Start.
- [x] Рамка Press Start на нижнем экране мигает и висит всё время сцены.
- [x] Один Start/касание на титуле ведёт сразу в главное меню (не перематывает сцену).
- [x] Бездействие на Press Start возвращает к логотипам (ролик не запускается).
- [x] Три слота сохранения; копирование, удаление и загрузка работают.
- [x] У слота есть счётчик процента прохождения.
- [x] Параметры слота: одна опция, лицо (портрет) справа/слева.
- [x] Список запросов: по три на странице; «Next» идёт по кругу, «Back» возвращает в меню.
- [x] Вкладка Movie: подменю (Anata no Tame Ni 2, Welcome II после открытия), ролики не зацикливаются.

## Катарина (Catherine) и игровой процесс

- [x] Катарина открывается в любой момент касанием значка или кнопкой Y.
- [x] Вкладки: путеводитель, заметки пером, Goods, четвёртая — Jack при пазле, Save вне пазла.
- [x] Сохранение в любой момент через Катарину (Remy/Koshi: через телефон).
- [x] Джек вставляется вручную: касанием или удержанием A (клавиша Z) со стрелками; выбор джека стрелками.
- [x] Числа в пазлах меняются и вверх/вниз, и влево/вправо; выбор джека замкнут по кругу.
- [x] Путеводитель: текст поверх полных страниц, переключатель текста, быстрое меню страниц; всегда открывается с первой страницы.
- [x] Карта на нижнем экране при ходьбе; счётчик шагов.
- [x] Всей игрой можно управлять стилусом.
- [x] После первого прохождения запроса автосохранение; при повторном — экран Edo и автосохранение, затем логотипы.

## Сцены (для сверки картинки)

- [x] R00: парковка, событие Lost and Found (три предмета проверены), Welcome II.
- [ ] R02: крыша, бассейн квадратный.
- [ ] R09: вывеска отеля крутится быстро; нет бутылок на стойке закусочной.
- [ ] R11: загрузка при входе в маяк.
- [ ] R14: в холле после радио-пазлов играет Gymnopédie.
- [ ] R18: титры, эпилог.

## Известные расхождения PS2/DS (не баги текстур)

Меню, Катарина, экран сохранения, ролики Welcome и клип на DS нарисованы заново; в локациях другой масштаб, часть пальм и мелких предметов убрана. Для файла данных эти текстуры пары в PS2 не имеют.

## Языки

Европейская DS-версия выбирает язык по системному (En, Fr, De, Es, It). Учесть в этапе 9 (пакеты перевода).

## Сохранения: экспорт и импорт (ручная проверка, 2026-11-01)

Подготовка. Рабочее сохранение лежит рядом с ROM: `~/Developer/games/fsar-ru/roms/<имя ROM>.sav` (64 КиБ). **Его не трогаем**: все проверки идут на копии.

```sh
cd ~/Developer/games/sunpetal && cargo build --release -p sunpetal-app
D=$(mktemp -d); ROM="$HOME/Developer/games/fsar-ru/roms/Flower, Sun and Rain - Murder and Mystery in Paradise (Europe) (En,Fr,De,Es,It).nds"
cp "${ROM%.nds}.sav" $D/a.sav          # копия настоящего сохранения
```

**А. Командная строка, без окна (игра не запущена)** — прогнано автоматически 2026-11-01, пункты 1–5 и размер 8 КиБ из п. 6 прошли: экспорт идентичен; файл 100 байт отклонён (rc=1, сохранение не тронуто); файл из 0xFF и нулевой отклонены; замена создаёт `.bak-*`, `a.sav` равен импортируемому; после 7 импортов остаётся 5 копий; другой размер (8 КиБ) принят с пометкой о размере. Настоящее сохранение в `fsar-ru/roms` не менялось. **Чужое сохранение (п. 6) проверено:** `~/Downloads/fsar-save/fsar-eu-100pct.sav` (100 % прохождение EU, 64 КиБ, заголовок `Flower_Sun_Rain`, от стороннего игрока 2011 года, рядом `.duc` и `description.txt`) импортируется (rc=0, `cmp` совпадает) и игра его читает: безголовый запуск `sunpetal-debug --save` по START попадает в отель с шкалой шагов 20193, а с пустым сохранением идёт вступление с машиной и шкала 0 (снимки `artifacts/saves/cmp.png`, не в git). Размер 64 КиБ подтверждён настоящим сохранением. Остаются блоки Б и В (кроме размера и `.sav` из другого эмулятора).
1. `target/release/sunpetal-app "$ROM" --save $D/a.sav --export-save $D/out.sav` → `cmp $D/a.sav $D/out.sav` молчит (байты те же).
2. `head -c 100 /dev/urandom > $D/bad.sav; target/release/sunpetal-app "$ROM" --save $D/a.sav --import-save $D/bad.sav` → отказ с понятным сообщением («not a save file: 100 bytes…»); `a.sav` не изменился.
3. `python3 -c "open('$D/ff.sav','wb').write(b'\xff'*65536)"` (или нулевой файл `head -c 65536 /dev/zero`; `tr` под UTF-8 даёт двухбайтные символы, не годится) → импорт отвергается (пустое).
4. Подмена: взять `out.sav`, поменять байт (`printf '\x42' | dd of=$D/new.sav bs=1 seek=100 conv=notrunc` на копии), `--import-save $D/new.sav` → в `$D` появилась `a.sav.bak-ГГГГММДД-ЧЧММСС-NNN`, `a.sav` равен `new.sav`.
5. Сделать импорт 7 раз подряд: копий `.bak-*` остаётся 5.
6. Сохранение из другого эмулятора: положить `.sav` от melonDS/DeSmuME (если есть), импортировать, запустить игру на `--save` с ним: «Продолжить» видит прогресс. Если размер не 64 КиБ, в сообщении об импорте есть предупреждение.

**Б. Меню окна (перезапуск игры только по твоему слову)** — прогнано автором 2026-11-01 в живом окне: экспорт (файл 65536 байт, равен рабочему сохранению), импорт того же файла (диалог открылся и принял выбор после смены фокуса окна, см. B-10), игра перезапустилась сама (новый pid), рядом с сохранением появилась копия `….sav.bak-20261101-125548-000` (содержимое прежнего файла от 30 октября), рабочее сохранение равно экспортированному. Не отмечены автором: отмена диалога (п. 7), предупреждение первого нажатия (п. 4) и сообщение под настройками.
1. Запустить собранное приложение на копии: `target/release/sunpetal-app "$ROM" --lang ru --save $D/a.sav`.
2. Меню → «Экспорт сохранения…» → выбрать файл → под настройками строка об успехе; файл создан, `cmp` с `a.sav` молчит.
3. В игре дойти до сохранения у Эдо, сохраниться; снова экспорт; файлы различаются.
4. Меню → «Импорт сохранения…»: первое нажатие даёт только предупреждение («Импорт заменит сохранение… Нажмите ещё раз»), диалога нет; второе нажатие открывает выбор файла; выбрать ранний экспорт.
5. Игра перезапустилась сама; «Продолжить» показывает прежний (ранний) прогресс, а не только что сделанный. Рядом с `a.sav` лежит копия `.bak-*` с поздним прогрессом.
6. Подождать больше 5 секунд (автосохранение) и закрыть игру: `cmp $D/a.sav <ранний экспорт>` молчит (импорт не затёрт старой памятью машины).
7. Отмена диалога выбора файла: ничего не меняется, игра не перезапускается.

**В. Граничные случаи**
1. [x] (2026-11-01, защита от параллельного импорта сделана) Игра при старте берёт замок `NAME.sav.lock` (номер процесса), снимает при выходе; `--import-save` при живом процессе отказывает (код 1, сообщение называет процесс и файл замка), замок мёртвого процесса (после падения) не мешает; второй запуск на том же сохранении предупреждает; экспорт при запущенной игре разрешён. Проверено на настоящих процессах (`sunpetal-debug` как игра) и тестом `a_running_game_holds_the_lock_and_a_dead_ones_lock_is_taken_over`. Не проверено в окне: снятие замка при перезапуске из меню (по коду замок снимается в `nds::finish()` до запуска потомка).
2. Размер: какой размер EEPROM реально нужен игре (64 КиБ по умолчанию, не установлен): проверить на настоящем `.sav` из другого эмулятора (размер файла), сверить с размером нашего.
3. Android и iOS: кнопок нет (решение: только десктоп); при необходимости завести пункт этапа 10.

Результат прохода записать сюда (`[x]`/`[ ]` на каждый пункт) и баги — в `docs/BUGS.md`.

## Геймпад (Switch Pro), ручная проверка, записано 2026-11-01

Сделано в коде (`pad.rs`, `ui.rs`, `lib.rs`), без железа проверено только тестами таблицы кнопок, стилуса и меню. Нужно пройти автору на живом контроллере.

**Подключение (macOS).** Зажать на контроллере маленькую кнопку синхронизации сверху (рядом с USB-C), пока не замигают огни; Системные настройки → Bluetooth → «Pro Controller» → Подключить. Запускать приложение из терминала с журналом: `SUNPETAL_PAD_LOG=1 target/release/sunpetal-app` (журнал идёт в терминал: имя контроллера, каждая кнопка и ось, во что она опознана). Если кнопки в журнале называются не так, как ниже (например, оси вместо крестовины), приложить журнал к багу.

**А. Игра (меню закрыто).**
1. Крестовина и левый стик — ходьба и выбор; A (правая) — A игры, B (нижняя) — B игры, X (верхняя), Y (левая), L/ZL, R/ZR. Проверить, что A/B не перепутаны (по DS: восточная кнопка — A).
2. SELECT («−» на Switch Pro) — игровое меню чемодана Катарины: из сцены открывает меню (нижний экран), нажатие ещё раз/B — назад. В игру кнопка SELECT не уходит.
3. START («+») вне титула — открывается НАШЕ короткое меню (Звук, Экран и окно, Картинка, Сохранения, выход в главное меню). Игра на паузе (если стоит «Пауза, пока открыто меню»).
4. START на титуле («Press START») идёт игре, меню не открывается; после начала игры START снова открывает меню.
5. Правый стик — на экране появляется кольцо (стилус); наклон двигает его, мёртвая зона: лёгкое касание ничего не двигает. Клик правого стика (R3) — касание: в меню чемодана нажимает иконку/пункт, пока держишь — перетаскивание. Мышь снова в деле — кольцо исчезает.

**Б. Меню (оба).**
6. Крестовина или левый стик — фокус по пунктам (жёлтое кольцо), удержание повторяет; на ползунке влево/вправо меняют значение.
7. A — нажать/открыть список; в списке крестовина выбирает, A подтверждает; B закрывает список, второй B — меню.
8. START закрывает меню; при закрытии настройки сохраняются.
9. Пока меню открыто, кнопки игре не идут (персонаж не ходит).
10. «Выйти в главное меню»: первое нажатие — предупреждение, второе — перезапуск программы (игра заново с логотипов, не на горячую: машина игры — собранная программа со своими потоками, сбросить её внутри процесса небезопасно).

**В. Полное меню под флагом.**
11. `[ui] full_menu = true` в файле настроек (или запуск с `--full-menu`): START, F1, Esc открывают прежнее полное меню (Язык, Графика, Эффекты, Звук, Управление, Профили…). Без флага — короткое. На Android включено по умолчанию.

**Известные ограничения:** фокусом по egui управляют стрелки, поэтому на ползунке влево/вправо меняют значение, а не переходят к соседнему пункту (вниз/вверх выходят); если контроллер отдаёт крестовину осью, она опознаётся как D-pad (журнал: «D-pad as axes»), но в меню эти оси не читаются — тогда приложить журнал.
