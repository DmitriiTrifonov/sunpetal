# Инструменты отладки для вычитки перевода: ТЗ и план

Заказ от проекта перевода (`~/Developer/games/fsar-ru`, читать можно, писать нельзя). Пользоваться будет другой агент (Claude) при вычитке русского текста: быстро и воспроизводимо попадать в нужную реплику и получать машиночитаемый результат, без сборки рома и без прохождения меню. Всё из командной строки, вывод: JSON (stdout) и файлы (PNG).

## ТЗ (версия 2)

Контекст. Перевод хранится в таблице реплик: глава (C00–C18, плюс служебные), сцена (`Cxx_yy`), ID реплики (пять цифр, например `04026`). Скрипты сцен: файлы `.s` с репликами `[[ID` и тегом `<R>` (перенос). Сцены `Cxx_yy.txt` вызывают реплики через `<TEXT_EX>ID</TEXT_EX>`, говорящий задаётся `<SETFACE2>`. Окно диалога: не больше 3 строк, строка не шире 194 px (текст с x=10, красная граница окна около x=207), слова игра сама не переносит.

Стек: Rust. CLI на `clap` (derive), JSON через `serde`/`serde_json`, PNG через `image` или `png`. Лог построчно (JSONL), `flush` после каждой записи (читать можно, пока процесс жив). `--watch` на `notify`. Режимы отладки включаются фичей cargo `debug-tools`, обычная сборка не меняется. Ошибки через `Result` с понятным текстом, без `unwrap` на пользовательском вводе. Детерминизм автопрокрутки: фиксированный seed, время считается кадрами.

Пункты по приоритету (каждый: сначала кратко описать подход, потом реализовать):

1. `--dialogue-log out.jsonl`: на каждое открытое окно диалога строка JSON: сцена, ID реплики, номер лица говорящего (из движка, не по эвристике), итоговый текст после переносов, число строк, ширина каждой строки в px, флаг переполнения (больше 3 строк или шире 194 px), номер кадра. Ширину брать из рендера окна диалога в рекомпе, если он есть, а не считать отдельно.
2. `--goto C04_16` (опционально `--chapter 4`): запуск сразу в сцене. Если сцена зависит от флагов, добавить `--set имя=значение` (повторяемый) и описать, какие флаги нужны для разных веток. Не обходить логику игры, если это ломает состояние: остановиться и спросить.
3. `--text-dir путь`, `--watch`: движок читает реплики напрямую из `.s` (или из CSV) и перечитывает при изменении файла, без пересборки рома и новой игры. Если текущая реплика заменилась, показать её заново.
4. `--autoplay`: жмёт A после каждой реплики до конца сцены (детерминированно: одинаковые входные данные дают одинаковые кадры). На каждую реплику PNG окна диалога `out/<сцена>_<ID>.png`. Параметры: задержка в кадрах, максимум реплик, остановка на выборе ответа с записью вариантов в лог.
5. `--shot файл.png`, `--state`: текущая сцена, индекс реплики, портрет, значения флагов.

Если часть уже есть в проекте, использовать. Если для пункта нет информации о формате или движке: не выдумывать, сообщить, чего не хватает.

Требования:
- Один исполняемый вход (CLI), стабильная схема JSON, описание схемы в `docs/debug-tools.md` с примерами вызовов.
- Отладочные режимы под фичей `debug-tools`.
- Код как окружающий: стиль, именование, плотность комментариев; `Result`, без `unwrap` на пользовательском вводе.
- Тесты: разбор тегов (`[[ID`, `<R>`, `<TEXT_EX>`, `<SETFACE2>`), подсчёт ширины строки, по одному интеграционному тесту на `--goto` и `--autoplay` на тестовой сцене.
- Ром и игровые ассеты не коммитить и не класть в документацию. В логе только нужное для отладки; оригинальный текст в репозиторий не сохранять.
- MCP не внедрять: сначала CLI. Когда заработает, предложить 5 команд для обёртки: `goto`, `advance`, `screenshot`, `dialogue_log`, `reload_text`.
- Приёмка: пройти `--autoplay` на двух сценах из разных глав и сравнить результат с эталоном (два уровня ниже), приложить результат.
- Итоговый отчёт: что сделано, что нет и почему, как запускать, какие флаги нужны для главы 4 и главы 18.

## Решения заказчика (2026-10-25)

Эталон приёмки, два уровня:
1. **Объективный (основной, без эмулятора).** Лог реплик совпадает с источником: порядок ID, текст после переносов (`<R>` и `\n`) и число строк сверяются с файлами `.s` и таблицей `text/ru.csv` из fsar-ru.
2. **Визуальный.** PNG окна диалога сравниваются на глаз со скриншотами melonDS: `states/requests/cp_request_N.ml1` (старт каждого заказа, ром gfx16) и кадры `dumps/emu/walk/rN_NNN.png` от `macros/walk_request.txt`. Файлов в git нет, путь знает владелец проекта; если их нет под рукой, спросить, свои не подставлять. Пиксель в пиксель не требуется: положение текста, переносы, портрет, красная граница окна.

Тесты:
- Интеграционные `--goto` и `--autoplay` идут только с локальным ромом, без `SUNPETAL_ROM` пропускаются (как `boot`).
- Дополнительно тесты без рома, чтобы в CI было что запускать: разбор тегов (`[[ID`, `<R>`, `<TEXT_EX>`, `<SETFACE2>`) на синтетических скриптах и подсчёт ширины строки на заданных строках.

Бинарник: отдельный `sunpetal-debug`. Общий код остаётся в библиотеке (не копируется), бинарник включается через `required-features = ["debug-tools"]`, обычная сборка и `sunpetal-headless` не меняются.

## Что уже есть (проверено 2026-10-25)

- Скрипт ввода `--input VBL:КНОПКИ[:КАДРОВ],VBL:tap:X:Y`, снимки `--shots`, сохранение `--save`, время считается кадрами (прогон каждый раз один и тот же).
- Сгенерированный C вызывает `ARM_ENTER(c, key)` на входе каждой функции (ARM9, ARM7, оверлеи); при `g_arm_trace != 0` вызывается `arm_trace_enter`, сейчас пустой (`services.rs`). Это готовая точка для наблюдателей входа в функцию без правки сгенерированного кода: читать `r0..r3` и память гостя.
- `Machine::override_fn` заменяет гостевую функцию кодом хоста (пока нигде не применяется).
- Новая игра на пустом `.sav`: START каждые 100 кадров с 400-го доводит до первой сцены к ~2100-му кадру. Текст сцены лежит в основной RAM как распакованный `.s` (UTF-16LE с BOM, адрес `0x022EE6F4` у первой сцены), строки реплик дополнительно копируются в куче блоками с заголовком `0x5544`.
- Сделано под фичей `debug-tools`: `nds/debug.rs` (наблюдатели входа в функцию, журнал вызовов, `peek`, `find`), `session.rs` (сеанс: кадры, кнопки, касания, снимок, журнал вызовов), бинарник `sunpetal-debug --repl` (команды со stdin, ответ JSON-строкой). `sunpetal-headless` не тронут.
- Меню Эдо (после Press Start, Start Game, слот): Continue / Next Days / Request / Option / Back. «Request» (касание около x=200, y=272 на экране) открывает список R-00… по три на странице; касание выбирает, второе подтверждает; игра пишет «Play from the start of the selected request number». Это честный путь для `--goto` к началу главы. «Next Days» похоже на выбор дня: исследовать.

Чего нет и что придётся выяснять по коду игры (имён символов нет, только адреса):
- какая функция показывает реплику и где у неё номер лица, ID, готовый текст по строкам;
- откуда игра берёт ширину строки (есть ли функция измерения для шрифта; иначе считать по `font.nftr` отдельно, и это надо будет явно написать);

- где лежат флаги прогресса и какие из них влияют на ветки.

## Состояние на 2026-10-25 (веха: лог реплик работает)

Сделано (всё под фичей `debug-tools`, не закоммичено):

- `dialogue.rs`: `Tracker` (ID, текст, лицо показанной реплики), `line_widths` (ширина строк по шрифту игры).
- `session.rs`: сеанс (кадры, кнопки, касания, снимок), имя сцены по чтению `Chapter/Pack/Cxx/Cxx_yy.txt.z` с картриджа, события реплик с записью в JSONL со сбросом, `advance` (A каждые 60 кадров до новой реплики).
- `sunpetal-debug --repl`: команды `run N | press KEYS [FRAMES] | tap X Y [FRAMES] | shot FILE | log FILE|off | advance [FRAMES] | walk N [FRAMES] | shown | slots FROM [N] | peek ADDR[:LEN] | find TEXT | findhex HEX | calls FRAMES FILE [KEYS] | callsarg FRAMES LO[-HI] [KEYS] | callsstr FRAMES PREFIX | quit`; ответ на каждую: строка JSON.

Проверено на C00_01 (R-00, 8 реплик подряд): ID идут 01006…01013 подряд, лицо 1, сцена `C00_01`, ширины и число строк правдоподобны. Строка лога: `{"frame","scene","id","face","text","lines","widths","overflow"}`.

Что и где лежит в игре (европейский ROM `YHNP`, ARM9, адреса постоянные):
- Скрипт сцены `.txt` игра исполняет сама, построчно (читалка строки `0203FAE4`, символа `0203FAC8`), состояние читалки в структуре `S` = `02074084`: `+4` номер строки `.txt`, `+0x10` буфер, `+0x18` индекс, `+0x1C` номер следующей команды, `+0x50` ID строки, которую грузит загрузчик.
- Прелоад: при старте сцены игра один раз проходит `.txt` и по каждому тегу строит запись команды: таблица указателей `02074BEC` (на команду по 0x40 байт): `[код, место в скрипте, параметры…]`. Тег → код: открывающий тег `<X>` = индекс в таблице имён `02065354` минус 133 (`SETFACE2` = 0x35, `TEXT_EX` = 0x36; закрывающие 0…132). Диспетчер: цепочка `bl обработчик; b конец` по 6 байт с `0203F410` (код 0x36 → `0204253C`, код 0x35 → `0204245C`).
- Загрузчик реплики `0204253C`: читает `.s` построчно, ищет `[[ID` (пять цифр) с ID из `S+0x50`, копирует текст в кучу, пишет указатель в `команда+8`. ID на входе функции ещё не известен: он ставится внутри (`0203F9D8`), поэтому наблюдатель стоит на `0203FAE5` (читалка строки) с `lr = 0204260F`.
- Текст, который показывает окно: указатель в `02075A28` (UTF-16, переносы `\n`); ID = ID команды, чей `+8` равен этому указателю; говорящий = первый параметр ближайшей раньше `SETFACE2` в таблице команд (линейный порядок команд: при ветвлениях сцены может отличаться от порядка исполнения; проверить на сценах с выбором).
- Шрифт окна: писатель `02075AFC` (`+0` шрифт NFTR в RAM, `+4` читалка символов), шрифт: `+2` глиф по умолчанию, `+4` ширины по умолчанию (левый отступ, ширина глифа, ширина символа), `+0xC` цепочка CWDH, `+0x10` цепочка CMAP. Ширина строки по формуле игры (`02033314`): сумма (ширина символа + 1) минус 1. Подставляет только пробел между буквами 1; расхождение с `linewidth.py` проверить по `accept-scenes.md` (допуск ±2 px).
- Имя файла сцены: строка `C00_01.TXT` лежит в кучевом объекте (`02296E98` на R-00), указателей на неё нет; поэтому сцена берётся из чтений картриджа.

Путь через меню без макроса (кадры от запуска, 100%-е сохранение, сеанс идёт кадрами; все касания по нижнему экрану): `run 2400`, `press START`, `run 200`, `press START`, `run 200`, `press START`, `run 150`, `press A`, `run 300`, `press A` (Start Game → слот), `run 400`, `press A`, `run 300`, `press A`, `run 400`, `tap 200 80`, `run 300`, `tap 200 80`, `run 300` (открыт список «Request»), `tap 150 19`, `run 60`, `tap 150 19` (R-00); затем `run 600` и `walk N` (R-00 стартует поездкой без окон, первая реплика на ~9300-м кадре, промежуточные A листают её). Страницы списка по три заказа, «Next» листает; «Next Days» в меню Эдо похоже на выбор дня (не исследован).

## План

0. **Основа.** Фича `debug-tools` в `sunpetal-runtime` (опциональные `clap`, `serde`, `serde_json`, `notify`, PNG), бинарник `sunpetal-debug` с `required-features`. Наблюдатели входа в функцию через `arm_trace_enter` (реестр `(cpu, key) → обработчик`, быстрый отказ, когда наблюдателей нет). Режим «гнать кадры до условия» и ввод кнопок из хоста. Модуль разбора `.s` и `.txt` сцен (теги `[[ID`, `<R>`, `<TEXT_EX>`, `<SETFACE2>`) с тестами на синтетических строках, без игрового текста.
1. **Лог реплик.** Журнал вызовов в окне первой реплики (новая игра, C00_01, известный ID) найти функцию показа и функцию измерения; наблюдатель пишет JSONL со сбросом буфера. Ширину брать из функции игры, если она найдётся. Лицо из переменной движка.
2. **`--goto`.** Разобрать загрузчик сцен. Сначала самый честный способ: меню «Request» (повторяет `fsar-ru/macros/to_request.txt`, запрос R-NN ведёт на начало главы; нужен слот с пройденными главами), затем переход к сцене внутри главы через очередь сцен игры. Если честного пути нет и нужна запись в память, остановиться и спросить. `--set` после того, как найдены флаги.
3. **Горячая перезагрузка.** Подмена источника `.s` (хук чтения файла сцены или запись в буфер после распаковки) и повторный разбор. Сначала выяснить, кэшируют ли реплики кучей (копии строк найдены), и как заставить игру перечитать. `notify` на папку, `--text-dir` из `.s` или CSV.
4. **Автопрокрутка.** Нажатие A по сигналу «реплика полностью показана» (от наблюдателя, не по таймеру), PNG вырезки окна, остановка на выборе (искать функцию меню ответов), лимиты: кадры задержки, число реплик.
5. **`--shot`, `--state`.** Снимок и JSON состояния по найденным адресам.
6. **Документация и тесты.** `docs/debug-tools.md` со схемой JSON; интеграционные тесты `--goto` и `--autoplay` (нужен ром: без `SUNPETAL_ROM` пропускаются, как `boot`); приёмка на главах 4 и 18, сверка с эталоном; предложение пяти команд MCP.

Теги скриптов: `PUTEVENT`, `REMOVEEVENT`, `CHANGEMAP(2)`, `CLOSE_CHAPTER`, `JUMP`. C04_16 и вторая половина C18_01 требуют ходьбы по отелю.

Решение заказчика (вариант а): писать значение шага, а героя довести честно. Сделано так (подробно в `debug-tools.md`): `evn.rs` (записи событий), `script::lz10`/`map_target`, `Session::goto_event` (шаг через обработчик `SETVALUE` игры `0204859D`, вызываемый из хоста на входе цикла событий `02023745` через `debug::inject`; двери по графу карт; герой на месте события). Адреса: значения истории `020742EC` (индекс × 4), указатель мира `0206B460` (первое слово — герой: позиция `+0x18/0x1C/0x20` в 1/4096, карта `+0x0C`), обработчик `CHANGEMAP` `02048669` (в свободной ходьбе не действует: карту меняет только исполнитель скриптов; двери — это скрипты событий `Ann_yy`), загрузчик сцены `0203F025`, цикл проверки событий внутри `02023745`.
