# GPU-бэкенд 3D — подробный план (2026-10-29)

Второй бэкенд рендера 3D поверх того же потока команд GX. Не замена программного рендера: софт остаётся эталоном, запасным путём и источником эталонных кадров. Предварительная версия плана расширена детализацией по коду; оценки уточняются после каждого этапа.

## Точки вставки (проверено по коду)

- `crates/sunpetal-runtime/src/nds/gx.rs`, `gx_render_start` (~строка 1165): собирает `Job` — непрозрачные полигоны сортируются по `sortkey` (y), затем прозрачные (тоже по y, кроме `render_manual`); копии текстурной VRAM, `TexKey` по кадру (`texture_keys`); вызывает `render3d::render(&job, self.scale)` и кладёт результат в `frame3d` (+`frame3d_wide`, `frame3d_scale`).
- `crates/sunpetal-runtime/src/nds/render3d.rs`: `render(job, scale) -> (Vec<u32>, notes)`; пиксель — «слово 3D»: R6G6B6 (6 бит на канал) | альфа 5 бит (бит 18) | контур 4 бита (24–27) | тень 4 бита (28–31). Слово смешивает с 2D-слоями композитор (`video.rs`), контур и тени красит он же; `outline_pass`/`shade_pass` работают по буферу глубины и ID.
- `crates/sunpetal-runtime/src/nds/mod.rs`: `Extras` (outline, outline_width, shadow, shadow_radius, msaa) — настройки эффектов, приходят из окна.
- Окно (`sunpetal-app`): `gfx.rs` берёт кадры (2D-экраны и 3D-слово) из `shared.frame`, эффекты и композит окна — в wgpu (`post.rs`, `effects.rs`).

Вывод: GPU-бэкенд заменяет ровно одну функцию — `render(job, scale)` — и возвращает тот же `Vec<u32>` слов. Всё выше (`gx_render_start`) и ниже (`compose`, эффекты, окно) не меняется, кроме выбора бэкенда.

## Общая архитектура

- Новый модуль `crates/sunpetal-runtime/src/nds/render3d_gpu.rs` за cargo-фичей **`gpu`**; `wgpu = "х"` — опциональная зависимость `sunpetal-runtime`, версию выровнять с `sunpetal-app` (одна версия на workspace).
- Выбор бэкенда: поле в `Nds` (`renderer: Renderer`), `enum Renderer { Software, Gpu(GpuCtx) }`; строится из настроек (`[video] renderer = "software"|"gpu"`, умолчание — software) в момент первого `gx_render_start` (там уже есть устройство и масштаб).
- Контекст: свой `wgpu::Instance` внутри рантайма (окно приложения имеет свой — два логических устройства на процесс допустимы и изолируют рантайм от меню/эффектов; если профилирование покажет лишнюю копию памяти текстур — объединить через общий `Instance`, не раньше).
- Данные кадра в GPU: вершинный буфер (`GxVertex` как `#[repr(C)]`, выровнять поля — f32/ i32 микс), индексный буфер треугольников из полигонов (fan по `n` вершинам; веера выпуклые после клиппинга GX — подтвердить на кадрах), юниформ-блок для скаляров кадра (wbuffer, alpha_ref, clear, fog, toon, edge, размеры), текстуры в кэше по `TexKey`.
- Обратно: readback в `Vec<u32>` через staging-буфер (`copy_texture_to_buffer` + `map_async`, пайплайн из 2 кадров в полёте, чтобы не стоять). Упаковка слова — отдельным compute-пасом или сразу рендером в `r32uint`: прозрачным нужен float-blend, поэтому два аттачмента (цвет `rgba16float`, служебный `r32uint`: ID полигона + биты контура/тени) и финальный compute-пас упаковки в слово.

## Этап 0. Эталоны и набор сравнения (без GPU)

- **Дамп кадра**: при переменной окружения `SUNPETAL_JOB_DUMP=DIR` в `gx_render_start` после сборки `Job` сериализовать его (заголовок: scale, width, счётчик кадра; тело: len-prefixed вершины, полигоны, регистры, таблицы, tex/texpal-копии, ключи; пак замен — по ссылке на ключи, грузится отдельно). Дампы в `.gitignore`, в репозиторий не попадают.
- **Кадры-эталоны** (снять софтом, по 1–3 сцены на пункт): логотипы без 3D (пустой кадр), диалог C04_03, мост/поездка, парковка (тун, полупрозрачные полосы «on air», полигонов 400+), сцена с контуром 0,25 и тенями, ролик, широкий E=43 и E=170, кейс Катарины (квады-интерфейс), включённая супервыборка msaa=2 (эталон краёв для будущего MSAA).
- **Набор сравнения** `tests/gpu_parity.rs` (feature `gpu`): читает дамп, гоняет софт и GPU, сравнивает слова попиксельно; отчёт: доля совпавших, средняя |Δ| по каналам, карта отличий в PNG (отличившийся пиксель — красным), список первых N худших точек с их полигонами (по глубинной карте).
- Приёмка: круговорот дамп → загрузка → софт-рендер даёт байт в байт слова живого кадра (тест на 3 кадрах).

## Этап 1. Каркас: непрозрачные без текстур

- WGSL: вершинный шейдер из `sx/sy` (пасsthrough, пиксельная сетка сохраняется) и из clip-координат (полная точность, для будущего MSAA) — **два входа, выбор константой шейдера**; фрагментный: gouraud-цвет, depth-тест.
- Глубина: сначала float32 с линейной интерполяцией 1/w; сравнение с `clear_depth` и квантованием до 15 бит (`depth <= текущий`, зеркально софту) — расхождения собрать на этапе 5.
- Рендер в `rgba16float` + `depth32float`; упаковка слова (альфа 31 у непрозрачных) и readback.
- Приёмка: 3 непрозрачные сцены в допуске (средняя |Δ| ≤ 1/63, пикселей с |Δ| > 2 ступеней < 0,5 %); карта отличий пустая по краям полигонов (клиппинг веера совпал).

## Этап 2. Текстуры

- Распаковка DS-форматов в RGBA при появлении нового `TexKey` (кэш LRU ~64 МБ; инвалидируется «поколением» текстурной памяти, как в `texpack.rs`): форматы 4/16/256 цветов, A3I5, A5I3, direct, сжатые 4×4 (все 4 режима интерполяции + палитра-исключение), перестановка индексов T8 (биты 3–4).
- Замены из пака: тот же путь `Pack`/`TexKey`, сэмплинг как `sample_image` (координаты в текселях оригинала, wrap/flip по флагам `TEXIMAGE_PARAM`).
- Сэмплер: nearest по умолчанию; **alpha-взвешенный bilinear — свой код в шейдере** (как `bilinear` в `render3d.rs`: прозрачный тексел не протекает), не аппаратный. Флаг `[effects] texture_filter`.
- Режимы накрытия: modulate/decal/toon-highlight/shadow (биты `POLYGON_ATTR` 4–5), включая правило «текстура без канала альфы» для direct.
- Приёмка: по одному синтетическому кадру на формат (эталон рисует софт) + парковка целиком; пороги как в этапе 1.

## Этап 3. Тун, туман, задняя плоскость

- Тун: таблица 32×u16 → текстура `rgba8` 32×1, lookup по освещённости в шейдере.
- Туман: таблица 32-ступенчатая (сдвиг `fog_offset`), режимы «цвет и альфа»/«только альфа» (`DISP3DCNT` бит 7), бит тумана на полигоне.
- Задняя плоскость: битмап из VRAM (слоты 2/3, `CLRIMAGE_OFFSET`) как текстура 256×256; правило смешения с `clear_color`.

## Этап 4. Прозрачность

- Прозрачные — во втором draw-пасе строго в порядке подачи (порядок уже собран в `Job.polys`, hardware blending с уравнением DS: `(src·a + dst·(31−a))/32`, `a` — 5-битная альфа полигона); запись глубины прозрачными — как в софте (проверить бит 12 `POLYGON_ATTR`).
- Alpha-тест `alpha_ref`; 1-битная альфа (бит 11) — рвёт текстуру по порогу, не блендит.
- Тени-полигоны (режим 3): штамп-поведение через сравнение ID в служебном аттачменте (софт их в кадрах не встречал, реализовать по описанию, сверить синтетикой).
- Каждый прозрачный пиксель пишет ID полигона в служебный аттачмент (нужен контуру) — при перекрытии берёт последний, как софт.
- Приёмка: парковка с полосами «on air» (альфа 14/31) и сцена с окном реплики (полупрозрачные плоские квады) в допуске.

## Этап 5. Точность глубины и порядок (кванты расхождений)

Главный источник «почему у GPU другой пиксель»: DS сравнивает 15-битный w (или z), интерполированный по вершинам с фиксированной точностью; GPU — float. Подэтапы с контрольными точками:

- **5.1 Инструмент замера глубины — закрыт 2026-10-29.** Дамп и харнесс получают карту глубины софта на пиксель (эталон w/z) — сейчас сверяется только слово, а источник «другого пикселя» именно глубина: в `jobdump`/`Target` вытащить глубину, в харнесс — сравнение глубины GPU против софта отдельно от слова (свой допуск по глубине). **КТ:** на 16 дампах известна карта отличий глубины — **сделано: 16/16 дампов глубина бит-в-бит (mean 0, max 0 шагов), карты отличий пустые**.
- **5.2 Квантование глубины до 15 бит — закрыт 2026-10-29 (решение: не квантуем).** В WGSL квантовать глубину перед тестом и записью (`floor(d·32768·чёткость)` — формулу снять с `render3d.rs`: `clear_depth`, 15-битный w), замерить с квантованием и без, оставить вариант с меньшей картой отличий. **КТ:** карта отличий глубины парковки пустая (или допуск зафиксирован числом), решение «квантуем/не квантуем» записано в журнал — **сделано: без квантования 0 отличий, с квантованием 36 580–49 041 пикселя на кадр; решение «не квантуем» в журнале**.
- **5.3 Крайние случаи порядка — закрыт 2026-10-29.** Юнит-тесты: вершина за камерой (границы после клиппинга GX), полигоны с одинаковым w (стабильный порядок), прозрачный поверх прозрачного на равной глубине (порядок подачи против `eq_depth`). **КТ:** тесты зелёные, поведение детерминировано и равно софту — **сделано: 3 новых теста байт-в-байт; бит 14 в 16 дампах не встречается (0 полигонов)**.
- **5.4 Слепой прогон 30 000 кадров — закрыт 2026-10-29.** Минимальный крюк выбора бэкенда `--renderer gpu` (вынести минимум из этапа 8: `enum Renderer` + флаг, без меню/конфига), headless-прогон без паник, лог «once»-замечаний совпадает с софтом. **КТ:** 30 000 кадров без паник и без новых «once»-замечаний — **сделано: 30 000 кадров на GPU без паник, diff логов = одна строка (имя save-файла), «GPU renderer failed» = 0**.

Приёмка этапа в целом: карта отличий парковки пустая; 30 000 кадров слепого прогона без паник и с тем же логом. Зависимость: 5.4 тянет минимум `Renderer`/`--renderer` из этапа 8 — зафиксировать в 8.1, что минимум уже есть.

## Этап 6. MSAA

Цель: аппаратный 4× вместо супервыборки софта (`render` софта рисует в k раз больше и `resolve` вниз; GPU заменяет это `sample_count=4` + своим резолвом). Подэтапы:

- **6.1 Субпиксельная геометрия из clip-координат.** Второй вход вершинного шейдера (clip `x/y/z/w` вместо `sx/sy`) — иначе аппаратный MSAA не имеет смысла. Путь `sx/sy` сохранить для parity-режима (пиксельная сетка). **КТ:** parity-режим (sx/sy) по-прежнему 16 из 16 байт-в-байт; clip-вход даёт ту же картинку на неперекрывающихся кадрах.
- **6.2 Аппаратный 4× (`sample_count=4`).** Все аттачменты геометрии/бленда `sample_count=4`; полигоны рисуются из clip-координат. **КТ:** MSAA-кадр (до резолва) на краях совпадает с софт-супервыборкой msaa=2/4.
- **6.3 Свой resolve compute-пас.** Альфа-взвешенный резолв 1:1 к `resolve` софта (цвет по альфе, альфа = доля покрытия, контур/тень по покрытым) — не аппаратный resolve. **КТ:** сверка с софт msaa=2/4 на эталонных кадрах в допуске (не пиксельный паритет — субпиксельная сетка отпущена сознательно).
- **6.4 Бюджет и замер.** Убрать `effective_msaa`-формулу (масштаб × выборки, `effects.rs`): стоимость ≈1,5× вместо k², ограничение остаётся по памяти. Замер fps: GPU MSAA 4× при scale 4 быстрее софта msaa=2 минимум вдвое. **КТ:** цифры fps записаны в журнал.

## Этап 7. Контур, тени, широкий кадр

Цель: биты 24–31 слова (outline/shade) и заливка боков. Сначала расширить накопление GPU — сейчас есть только `id`/слово/штамп/глубина, а `outline_pass`/`shade_pass` софта читают ещё `oid`, `cover`, `trans`. Подэтапы:

- **7.0 Служебные аттачменты — закрыт 2026-10-29.** Добавить к накоплению `oid` (ID последнего непрозрачного), `cover` (насколько прозрачные скрывают пиксель, 0–31) и `trans` (глубину писал прозрачный) — ровно как `Target` софта. **КТ:** на 16 дампах эти карты совпадают с софтом (через расширенный дамп/харнесс) — **сделано: 16/16 байт-в-байт**.
- **7.1 Контур (`outline_pass` в WGSL) — закрыт 2026-10-29.** Compute-пас 1:1: пары пикселей, `OUTLINE_STEP`, `INTERFACE_DEPTH`, `HIDING_ALPHA`, ослабление `cover`, `SILHOUETTE`; выход — биты 24–27. **КТ:** биты контура совпадают с софтом ≥ 95 % пикселей на кадрах с контуром — **сделано: 16/16 дампов биты контура 100 % (слова байт-в-байт)**.
- **7.2 Тени (`shade_pass` в WGSL) — закрыт 2026-10-29.** Compute-пас: 3 луча, `JUMP`, penumbra, `cover`/`dim`; выход — биты 28–31. **КТ:** биты теней ≥ 95 % — **сделано: 16/16 дампов биты теней 100 % (слова байт-в-байт)**.
- **7.3 Edge marking (бит 5 `DISP3DCNT`) — закрыт 2026-10-29.** Краевой цвет по ID соседа (`id[j] != id[i] && depth[j] >= depth[i]`) в шейдере; снять маску `0x20` из `stage4_job`. **КТ:** кадры с edge marking совпадают с софтом — **сделано: 16/16 дампов байт-в-байт (234–2480 краевых пикселей на сценах)**.
- **7.4 Широкий кадр (`extend_sides` в WGSL) — закрыт 2026-10-29.** Заливка боков по глубине ≥ `FAR`/`SKY` (0.999/0.99996) тем же compute-пасом упаковки; снять `SUNPETAL_NO_EXTEND`. **КТ:** кадр E=170 по картам отличий без новой геометрии — **сделано: E=43 и E=170 байт-в-байт (65 664 и 114 432 пикселя, 15 085 и 63 194 боковых пикселей с контентом)**.

Приёмка этапа в целом (закрыта 2026-10-29): те же кадры, что у софта с включёнными контуром/тенями, биты 24–31 совпадают ≥ 95 % пикселей — получено 100 %; широкий кадр E=170 — без новой геометрии — получено байт-в-байт.

## Этап 8. Интеграция и производительность

Цель: включить GPU-бэкенд в приложение и померить. Подэтапы:

- **8.1 Выбор бэкенда.** `enum Renderer { Software, Gpu }` в `Nds`, `--renderer` у `headless`/`debug`, `[video] renderer` в конфиге, пункт в меню (`ui.rs`); ошибка создания устройства — понятное сообщение и откат на software (однократно, не в цикле). (Минимум `Renderer`+`--renderer` уже вынесен в 5.4 для слепого прогона.) **КТ:** переключение в окне работает, откат без паники.
- **8.2 Пайплайн кадров.** Кольцо из 2–3 readback-буферов: рендер кадра N+1 не ждёт readback кадра N (сейчас `map_async` синхронный). **КТ:** замер не упирается в последовательный readback.
- **8.3 Замеры fps.** Методика из `docs/STATUS.md`: тяжёлая сцена, scale 1–4, софт vs GPU; цель — GPU при scale 4 держит 60 fps там, где софт даёт ≤ 51; телефон (Flip7) — отдельный замер. **КТ:** цифры записаны в журнал.
- **8.4 Zero-copy в окно.** 3D-текстура из рантайма в `gfx.rs` без readback — отдельным шагом, если readback в профиле заметен. **КТ:** сделано или отложено с замером.
- **8.5 CI.** Feature `gpu` собирается на всех трёх ОС без устройства; тесты паритета помечены `#[ignore]` и гоняются локально. **КТ:** CI зелёный.

## Риски

- **w-буфер и порядок прозрачных** (этап 5): если квантование не уберёт расхождения — двухпроходный порядок для конфликтующих полигонов (дороже, но редко нужен).
- **Пиксельная сетка DS против субпиксельного GPU**: 1-пиксельные квады интерфейса и контур чувствительны; в parity-режиме `sx/sy` сохраняют сетку, в MSAA-режиме сетка отпускается сознательно (сверка только с софт-супервыборкой).
- **Readback** на отдельных драйверах; лечение — zero-copy (этап 8).
- **wgpu на Android/Vulkan-драйверах телефонов**: рантайм-часть переносима, но замер на устройстве запланирован отдельно; худший случай — софт на телефоне остаётся.
- **Расползание объёма**: шаги 6–7 не блокируют запуск; бэкенд считается годным после этапа 5.

### Этап 7.4 — Широкий кадр (extend_sides в WGSL) — закрыт 2026-10-29

### Этап 5.3 — Крайние случаи порядка — закрыт 2026-10-29

**Разведка (числа, для журнала):** скан 16 дампов — **бит 14 (`eq_depth`) не выставлен ни у одного полигона** (0 из ~5 000). То есть equal-depth тест в реальных кадрах не встречается; покрыт только синтетикой.

**Наблюдение (не блокирует, на слепой прогон 5.4):**
- Непрозрачные идут аппаратным `Less`-тестом, который `eq_depth` не умеет (в шейдере он есть только у прозрачных/теней). Если бит 14 встретится на непрозрачном полигоне в живом кадре — GPU разойдётся с софтом (у софта допуск, у GPU строгое `Less`). **Артефакты:** нет новых.

### Этап 5.2 — Квантование глубины до 15 бит — закрыт 2026-10-29 (решение: не квантуем)

**Что сделано (по пунктам плана):**

- **Аудит пути глубины софта** (`render3d.rs`): `clear_depth` (стр. 276) — это *расширение* 15-битного источника в 24-битный float, единственное место, где «15 бит» вообще появляется; вершины w/z — fixed-point только на источнике (данные GX), дальше весь путь в f32 без квантования: `depth_of` (конверсия), интерполяция `l0·da + l1·db + l2·dc`, тест `depth >= d` / `(depth − d).abs() > tol` (стр. 436), запись `t.depth[i] = depth`. GPU повторяет путь бит-в-бит (замерено в 5.1).
- **Формальный замер «с квантованием и без»** в харнессе: `AuxParity.depth_quantized_diffs` / `depth_quantized_max_steps` — эталонная глубина софта, округлённая до гранулярности 15 бит (512 шагов из 24-битных, сетка w-буфера: `round(d·32768)/32768`), сравнивается с её же float-значением; тест печатает счётчик на каждый дамп.

**Приёмка (числа):**

- **Без квантования** (текущий код): **0 отличий** на 16/16 дампах (бит-в-бит, этап 5.1).
- **С квантованием**: **36 580–49 041 пикселя из 49 152** на 13 из 16 дампов (максимум 256 шагов = половина гранулярности); 3 дампа (логотипы, титул) не меняются — их глубины уже лежат на 15-битной сетке (плоские сцены).

**Решение: не квантуем.** Эталон (софт) глубину не квантует, GPU уже совпадает бит-в-бит; квантование ввело бы десятки тысяч отличий на кадр. **Отклонение от плана:** квантование не реализовывалось в WGSL — замер сделан симуляцией на эталонной глубине; это строго показывает «хуже», не внося заведомо мёртвого кода в шейдер.

**Артефакты:** новых нет (цифры — в выводе теста).

### Этап 4 — Прозрачность — закрыт 2026-10-29

**Что сделано (по пунктам плана):**

- **Прозрачные — во втором draw-пасе в порядке подачи.** `Job.polys` уже отсортирован (непрозрачные, потом прозрачные); `build` делит геометрию на один буфер непрозрачных (один пас с аппаратным `Less`-тестом глубины, как раньше) и по буферу на каждый прозрачный/теневой полигон. Каждый прозрачный полигон рисуется **в отдельном рендер-пасе** строго в порядке `job.polys`: накопленная картинка (слово, ID полигона, штамп-маска, глубина) пин-понгится между двумя наборами текстур (`copy_texture_to_texture` + рендер + свап), чтобы шейдер читал результат предыдущего полигона и смешивал поверх него. Глубинный тест прозрачного — в шейдере против накопленной глубины (`depth >= d` → за, бит 14 = тест «равно» с допуском `0x200/16777215`).
- **Блендинг DS — в шейдере, не аппаратный** (отклонение от плана): уравнение `(src·(a+1) + dst·(31−a))/32` (5-битная альфа полигона после текстуры) нельзя выразить аппаратными факторами блендинга (`+1`-смещения и «альфа = max, не смесь»), поэтому `fs_trans` читает накопленное слово и пишет смесь сам. Случаи «альфа накопления 0 → просто запись», «`oa >= 31` → перезапись», «прозрачный не рисуется поверх своего ID» (`id == pid && alpha in 1..30`), «`!blend_on` → прозрачный рисует непрозрачно» — ровно по софту.
- **Alpha-тест** `alpha_ref` перенесён в общий `shade` (раньше только для непрозрачных) — теперь и для прозрачных; **1-битная альфа** (текстуры с альфой 0/31 и A3I5/A5I3) — естественно формулой modulate `oa = ((ta+1)·(polyalpha+1)−1)/32`, отдельного бита не понадобилось (в плане «бит 11» — это на самом деле `write_trans_depth`).
- **Тени-полигоны (режим 3)**: маска (ID 0) рисует только в отдельный аттачмент `stencil` (1, где «за»), тень (ID ≠ 0) — смешивается только где `stencil == 1 && id != pid`. Реализовано отдельным пайплайном `mask` (один цветовой таргет) + общий `blend`.
- **Запись глубины прозрачными** — бит 11 `POLYGON_ATTR` (`0x800`): `depth_out` пишется глубиной полигона только при нём, иначе копируется накопленная.
- **Вернулись форматы A3I5/A5I3** (fmt 1/6, отложенные с этапа 2): их распаковка уже была в `texpack::decode`, теперь их полигоны попадают в прозрачный пас (`translucent` в `GxPoly` их и так помечает).
- `stage3_job` → `stage4_job`: из сравнения выкинут только wireframe (`polyalpha == 0`); прозрачные и тени вернулись. Харнесс переключён.

### Этап 3 — Тун, туман, задняя плоскость — закрыт 2026-10-29

**Что сделано (по пунктам плана):**

- **Тун** остался в юниформе (`array<vec4u, 8>`), как на этапе 1 — таблица уже байт-в-байт и проходит паритет; перекладывать её в текстуру `rgba8` 32×1 смысла нет (lookup по `r6 >> 1` в шейдере и так работает). Отклонение от плана, см. ниже.
- **Туман**: второй рендер-пас поверх готовой картинки. Слово, флаг тумана и глубина пишутся в три отдельных аттачмента геометрии (`R32Uint` слово, `R32Uint` флаг, `R32Float` глубина; глубинный тест по-прежнему аппаратный `Less` в `Depth32Float`), затем полноэкранный квад читает их и движет пиксель к цвету тумана (`fmix`: `(a·(128−d)+b·d)>>7`) и альфу по плотности на его глубине. Плотность — `fog_density` в WGSL: 32 записи `fog_table` (упакованы `array<vec4u, 8>`, по 4 u8 в компоненте), шаг `0x400 >> shift` (биты 8–11 `DISP3DCNT`), сдвиг `fog_offset`, линейно между записями, за краями — крайние; `d/256 & 127`, 127 → 128. Режимы «цвет и альфа»/«только альфа» — бит 6 (`0x40`) `DISP3DCNT`, включение — бит 7 (`0x80`); бит тумана на полигоне — бит 15 `POLYGON_ATTR` (в `Tri` добавлено поле `fog`, флаг пишется в аттачмент фрагментом, прошедшим глубину — как софт пишет `t.fog[i]` только у прошедших). Финальный проход заодно обнуляет слово при альфе 0 (`if alpha == 0 { 0 }`, как `render_at`) — это закрыло несовпадение, которое принесла бы задняя плоскость с прозрачными пикселями (слово с альфой 0, но ненулевым цветом).

### Этап 2 — Текстуры — закрыт 2026-10-29

**Что сделано (по пунктам плана):**

- **Распаковка DS-форматов** в кэш по `TexKey` (`decoded()`): тот же `texpack::decode`, что пишет PNG-дампы, поэтому содержимое текселов байт-в-байт совпадает с софтом по построению. Форматы 2/3/4/5/7 покрыты (1 A3I5 и 6 A5I3 не нужны: полигоны с ними всегда полупрозрачные и отфильтрованы до этапа 4 — отклонение от плана, см. ниже). Кэш — глобальный `Mutex`, LRU-штампы, бюджет 64 МБ; ключ контентный (хэш данных+палитры+формата), так что инвалидация «поколением» не нужна — новое содержимое это новый ключ. Ключи берутся из `job.keys`, при пустой карте считаются `texture_key` на месте.
- **Атлас на кадр**: `Rgba8Uint`-текстура, полочная упаковка (сортировка по высоте), один регион на `(tex, pal)`; `queue.write_texture` по регионам. Проверка на предел размеров устройства. `textureLoad` в шейдере — точные байты, без фильтрации железа.
- **Сэмплер**: nearest по умолчанию; **alpha-взвешенный bilinear своим кодом в WGSL** (прозрачный тексел не протекает — та же формула, что `bilinear` в `render3d.rs`), флаг `[effects] texture_filter` в юниформе. Оба сэмплера возвращают (r, g, b) 6-бит, alpha 5-бит (как `sample`/`bilinear` софта); конверсия байт атласа → 6/5 бит живёт в `tex_nearest` (сначала по ошибке делалась в шейдере повторно — 63>>2 = 15, поймано юнит-тестом).
- **Wrap/flip**: `wrapi` в WGSL повторяет `rem_euclid`/`div_euclid` софта для repeat+flip и clamp; флаги из `TEXIMAGE_PARAM` (биты 16–19) + бит «замена из пака» (координаты масштабируются `s / ow * w` — ровно порядок операций `sample_image`).
- **Замены из пака**: тот же `job.keys` → `Pack::get`; изображение кладётся в атлас со своим размером, сэмплинг по координатам оригинала (как `sample_image`).
- **Режимы накрытия**: modulate/decal/toon-highlight в шейдере (`POLYGON_ATTR` биты 4–5); toon-highlight: серый по красному вершины, потом текстура, потом прибавка цвета таблицы (порядок софта, раньше прибавка была до текстуры — исправлено). Для непрозрачных полигонов альфа тексела «всё или ничего» (0 → discard, 31 → запись), альфа-тест per-pixel (`oa <= alpha_ref`).
- `stage2_job` вместо `stage1_job` (текстурные полигоны вернулись в сравнение; полупрозрачные, mode 3, wireframe по-прежнему отфильтрованы); харнесс `gpu_parity_check` переключён, допуски этапа 1 (mean |Δ| ≤ 1/63, over2 < 0,5 %, edge_diffs = 0).
- Юнит-тесты (12 новых, всего 18 в модуле): по форматам 2/3/4/5/7 (+c0t, +сжатые все 4 режима интерполяции), direct с битом альфы, wrap repeat+flip с отрицательными координатами, decal, toon-highlight с текстурой, замена из `tiny.spdata`, bilinear (lone-red + градиент), альфа-тест, смешанный кадр. Все — байт-в-байт против софта.

**Точность GPU-арифметики — главная работа этапа.** Три расхождения GPU и софта пойманы юнит-тестами и кадром монолога, все — на «лезвиях» (texel-граница, где ±1 ulp переворачивает floor):

1. **Деление на GPU не корректно округлено** (Apple GPU: ±1–2 ulp, CPU: IEEE). Написан `div()` в WGSL — два шага Ньютона: остаток через точный `fma`, поправка второго порядка → результат в долях ulp. Вся цепочка (l = w/area, q = p/den, w-буфер, to6, bilinear-итог) идёт через него.
2. **Metal контрактирует `r += k·c` в FMA** (одно округление вместо двух, как в Rust). Везде, где софт округляет произведение и сумму отдельно, стоит трюк `fma(x, y, 0.0)` (равно `fl(x·y)` и не сворачивается обратно, т.к. `fma(x,y,0) ≠ x·y` из-за −0) — интерполяция, глубина, накопление bilinear.
3. **Metal контрактирует `a·b − c·d` в `fma(a, b, −c·d)`** — при катастрофическом сокращении в edge-функции это дало 4 ulp на w1, каскадом p1 +5, den +1, q0 −1 → другой тексел на полосе сжатой текстуры в монологе. edge() переписана на два `fma(·,·,0)` и вычитание.
4. Позиция фрагмента у растеризатора на ulp не совпадает с точным центром пикселя → шейдер привязывает `floor(pos)+0.5` (как `x as f32 + 0.5` софта).

**Приёмка (числа):** `SUNPETAL_JOB_DUMPS=build/gpu-parity/dumps SUNPETAL_JOB_DIFFS=build/gpu-parity/diffs cargo test --release -p sunpetal-runtime --features gpu --test gpu_parity` — **16 из 16 дампов: 100 % совпавших слов**, mean |Δ| = 0, over2 = 0, edge_diffs = 0, карты отличий пустые (0 красных пикселей). Требовалось: синтетика по форматам + парковка целиком в допусках — получено 16 кадров байт-в-байт, включая сцены с сотнями текстурных полигонов (в монологе 440 текстурных из 443). Полный набор тестов с фичей `gpu` и без — зелёный; сборка workspace без фичи — ок.

**Артефакты (в `.gitignore`):**

- `build/gpu-parity/diffs/*.png` — карты отличий этапа 2, по одной на дамп, все пустые.

**Отклонения от плана:**

- Форматы A3I5/A5I3 не распаковываются (в кадр не попадают: такие полигоны всегда полупрозрачные — фильтр этапа 4). Их поддержка вернётся с прозрачностью.
- Кэш — контентно-адресуемый по `TexKey` без «поколений» (инвалидация не нужна); LRU по штампу последнего использования.
- Юнит-тесты покрывают синтетику по форматам, приёмка на реальных кадрах оказалась строже плана (все 16 байт-в-байт).
- В юниформе добавлено поле `bilinear` (фильтр из `extras`), отладочный канал `dbg` был временным и снят.

**Следующий шаг:** этап 3 (тун-таблица как текстура 32×1 вместо юниформа, туман, задняя плоскость).

### Этап 1 — Каркас GPU: непрозрачные без текстур — закрыт 2026-10-29

**Что сделано (по пунктам плана):**

- Новый модуль `crates/sunpetal-runtime/src/nds/render3d_gpu.rs` за cargo-фичей **`gpu`** (`wgpu = "30.0.1"`, как в `sunpetal-app`; `pollster` для ожидания адаптера): свой `Instance`/`Device` у рантайма, headless (без surface).
- Вершинный шейдер: два входа по плану не понадобились — пиксельная сетка этапа 1 живёт в экранных координатах `sx/sy` (вход из clip-координат нужен этапу 6, MSAA). Позиция в NDC: `y = 1 − y/h·2` — конвенция D3D/Metal wgpu 30 (NDC y+1 = верх), как в шейдере окна (`post.rs`).
- Фрагментный шейдер повторяет софт **точно**: фан-триангуляция на CPU (как `raster`: `(0,k,k+1)`, разворот при area < 0, **area.abs()** — баг с отрицательной площадью пойман гостиничным кадром), top-left-правило владения ребром (биты `owns`), перспективно-корректный цвет по 1/w, z/w-глубина теми же f32-формулами, `toon` (таблица 32×u16 в юниформе, паковка в `vec4u` из-за stride 16 uniform-массивов), alpha-тест 31 ≤ alpha_ref.
- Точная проверка «внутри/на ребре» — **в шейдере** по точным координатам треугольника (передаются отдельно); растеризуемая геометрия расширена на 0,5 px (сдвиг полуплоскостей в f64), так что покрытие GPU — надмножество пикселей DS, а вердикт ставит точный тест. Края полигонов совпадают байт-в-байт.
- Глубинный тест — аппаратный `Less` (зеркально софту: `depth >= d` → не рисовать; равные не рисуются), `Depth32Float`, клир `clear_depth`. Порядок полигонов — как в дампе (сортировка GX уже сделана); при `Less` равные глубины отвергаются независимо от порядка.
- Слово пакуется прямо во фрагментном шейдере в `R32Uint` (непрозрачный overwrite, альфа 31; клир-слово — load-операцией; пас упаковки rgba16float→r32uint не нужен до этапа 4/блендинга — отклонение от плана, зафиксировано). Readback — `copy_texture_to_buffer` + staging + `map_async` (синхронно; пайплайн из 2 кадров в полёте — этап 8).
- `stage1_job()` — фильтр кадра для сравнения: непрозрачные без текстур, без режима 3, без wireframe; выключены edge marking/fog/rear plane/wide/extras; эталон (софт) и GPU рендерят один и тот же фильтрованный кадр.
- `nds::gpu_parity_check()` + `GpuParity`: отчёт как у `parity_check` (vs отфильтрованный софт-эталон) + карта отличий RGBA + `edge_diffs` (отличившиеся пиксели у смены цвета — прокси «по краям полигонов»). Тест `tests/gpu_parity.rs::gpu_parity_on_real_frames` (feature `gpu`): допуски этапа 1 (mean |Δ| ≤ 1/63, over2 < 0,5 %, edge_diffs = 0), карты отличий в `SUNPETAL_JOB_DIFFS` (пишутся до проверок, чтобы падающий кадр оставлял карту). Без адаптера — тест печатает «skipped» и проходит (CI без устройства зелёный).
- CI: `cargo build -p sunpetal-runtime --features gpu` на всех трёх ОС (тесты паритета требуют адаптер — гоняются локально, как в плане этапа 8).
- Юнит-тесты модуля (6 шт., байт-в-байт софт vs GPU, пропускаются без адаптера): треугольник с дробными координатами (scale 1 и 2), два треугольника на общей диагонали (без зазора и двойного рисования), перекрытие с глубиной, w-буфер + toon-таблица, треугольник по часовой (регрессия area < 0), пустой кадр (клир-слово).

**Приёмка (числа):** `SUNPETAL_JOB_DUMPS=build/gpu-parity/dumps SUNPETAL_JOB_DIFFS=build/gpu-parity/diffs cargo test --release -p sunpetal-runtime --features gpu --test gpu_parity` — **16 из 16 дампов этапа 0: 100 % совпавших слов**, mean |Δ| = 0, over2 = 0, **edge_diffs = 0** на всех, карты отличий пустые (0 красных пикселей).
