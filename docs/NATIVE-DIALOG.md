# Диалог на ARM: разведка (K-174, шаг 164.1 пилота)

Основание: `docs/native-script-dispatch.csv`, сгенерированный C (`generated/recomp/p_arm9_012.c`, `p_arm9_013.c`). Рабочий документ, дополняется по ходу шага.

## 1. Обработчики шага сценария: тонкие (статически)

Команды диалога вызываются из шага `0x02045BC4`; сами они почти ничего не делают, а ставят флаги состояния:

| Команда (код) | Обработчик | Что делает |
|---|---|---|
| `<TEXT_EX>` (54) | `0x02049234` (19 строк) | берёт параметр команды (`*(*(0x0207596C+0x1C)+8)` = ID реплики) → `*(0x020759EC+0x3C)`; пишет `*(0x0207596C+0x48)=1`, `*(0x0207596C+0x4C)=0`, `*(0x020758EC+2)=0`, `*(0x020758EC+0x74)=1`; ставит метку скрипта `*0x0206577C = 0x14` (состояние «текст») |
| `<SHOWWINDOW>` (75) | `0x02049D14` | `*0x02078598 = 1` |
| `<HIDEWINDOW>` (74) | `0x02049D08` | `*0x02078598 = 0` |
| `<NEXTPAGE>` (4) | `0x02048064` | пустая (`bx lr`) |
| `<WAIT>` (9) | `0x02048078` | 18 строк, вызывает `0x020532B0` |
| `<SETFACE2>` (53) | `0x02049178` | 87 строк, `0x020245B0` (поиск персонажа), `0x0204DC34`, `0x0204DC6C` |
| `<WINK>` (105) | `0x0204A4FC` | 33 строки, `0x020245B0`, `0x02029260` |
| `<CHOICE>` (25) | `0x0204824C` | 2 строки |

Вывод: диалог — конечный автомат вне обработчиков; `TEXT_EX` только запускает его (состояние `0x14` в `0x0206577C`, ID реплики в `0x020759EC+0x3C`). Сам разбор страницы, вывод букв и ожидание нажатия идут в коде, читающем эти поля (`0x020758EC…`, `0x020759EC…`: 187+111 упоминаний в `p_arm9_012.c`, 67+31 в `p_arm9_013.c`). Это предстоит развести динамикой (следующий пункт).

## 2. Динамика: что читает и пишет поля диалога

Адреса состояния окна уже известны рантайму (`crates/sunpetal-runtime/src/dialogue.rs`, лог реплик): `0x02075A28` — указатель на показываемый текст (0, если окна нет), `0x02075A20` — слово «в окне лицо» (ставит `SETFACE2`), `0x02075AFC` — писатель (шрифт), таблица загруженных реплик сцены `0x02074BEC` (счётчик `0x020740A0`, загрузчик строки `0x0204253C`). Опкоды в памяти: `SETFACE2` 0x35, `TEXT_EX` 0x36.

Трасса `goto C01_01` + `watchw 02075A28 4 300 r` + `run 600` + `writes` (кадры 5427…6027, реплика «Better head to the lobby.»): к указателю текста обращаются функции `0x020192EC` (из `0x0204629F`, из `0x02047CC1`) и `0x0201929C` (из `0x02047C65`), то есть код вокруг `0x02047780…0x02047DE4`. Это не отрисовка диалога: функция из 780 строк C считает векторы/интерполяцию (`0x0201929C`, `0x020192EC`, поиск персонажа `0x020245B0`) и читает `0x020758EC`, `0x020759EC`, `0x02075A6C`, `0x020785A8`; по виду это движение камеры/персонажей на время реплики, а не вывод букв. Где игра выводит буквы и ждёт нажатия, ещё не найдено.

## 3. Что осталось по шагу

- Найти и описать функции вывода текста (писатель `0x02075AFC`: кто рисует буквы, в какие BG/OAM/VRAM, откуда страницы и `<R>`), ожидание нажатия (кто читает ввод), смену страницы (`NEXTPAGE` пуст — значит страница ведётся по тексту реплики).
- Таблица адресов состояния окна (страница, номер строки, позиция буквы, ожидание) в данных, не в коде.
- Список привязок к железу DS (VRAM/BG/OAM, регистры, vblank), отдельным разделом.
- Скрипт или команда REPL, воспроизводящая трассу.
