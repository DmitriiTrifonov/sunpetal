# Полная замена движка: план (решение автора 2026-11-08)

**Решение (K-165): полное go.** Цель — игра исполняется нативным Rust без ARM-кода игры; скрипты, таблицы и параметры — данные (моды). Порты на 3DS и Ayn Thor сейчас не нужны: это снимает требование «два физических экрана в интерфейсе», но не отменяет отвязку от DS (VRAM, регистры, vblank) — она нужна модам и стабильному движку. Основание — итог пилота: `docs/NATIVE-SCRIPT.md` §10. Основа: `docs/NATIVE-ENGINE-DESIGN.md` (границы, «никакого хардкода», `SceneView`), `docs/NATIVE-PILOT.md` (образец паритета).

Правила, как в пилоте: риск за флагом, умолчание не меняется, пока нет паритета и слова автора; нативное совпадает с ARM слово в слово (хэш кадров и слова состояния), расхождение — откат сцены на ARM; числа в данных, не в коде; подсистемы переносятся по одной, гибрид на переходе (`NATIVE-ENGINE-DESIGN.md` п. 8).

## Что неизвестно (поэтому первый этап — измерение)

Пилот измерил только тонкие обработчики. Не измерены: нативный рендер и ввод окна диалога (вариант Б), толстые обработчики (персонажи, камера, эффекты), и всё, что ARM делает вне команд сценария (ходьба, коллизии, загрузка карт и моделей, меню, чемодан, головоломки, звук, сохранение). Объём этапов 4+ уточняется после этапа 1; до этого их оценки не даём.

## Этапы

- [ ] **Э1. Измерение (разведка раньше переделки).** Результат — таблица «подсистема → строк ARM, чем привязана к DS, цена переноса по факту».
  - [ ] **Э1.1 Инвентаризация: что ещё исполняет ARM кроме шага сценария.** Профиль вызовов по кадрам (глава 1, ходьба, меню, головоломка, диалог): функции по подсистемам, доля времени и число функций. КТ (авто): таблица в данных (`docs/native-engine-inventory.csv`), воспроизводится скриптом.
  - [ ] **Э1.2 Пилот Б: нативное окно диалога.** Рисует нативный код (текст из таблицы реплик, шрифт, окно) вместо ARM-писателя в VRAM; ввод A — логическим событием. Флаг. КТ (авто): кадры сравниваются с ARM по окну диалога (допуск и сравнение — решить в шаге по данным пилота), слепой прогон глав 1–18; запись цены.
  - [ ] **Э1.3 Пилот толстого обработчика: персонажи** (`SETCHARPOS`, `SETMOTION`, `SETFACE2`, `WALKTO`…): структура персонажа в куче, позы и движение. КТ (авто): состояние персонажей совпадает с ARM по кадрам на наборе сцен; запись цены.
  - [ ] **Э1.4 Итог измерения.** Переоценка этапов 4+, порядок подсистем, запись в этот файл и `STATUS.md`. КТ (ручная): автор подтверждает порядок.
- [ ] **Э2. Нативная ВМ ведёт порядок команд** вместо шага `0x02045BC4` (за флагом; разбор уже совпадает с игрой, K-162). КТ (авто): слепой прогон 18 глав, порядок и кадры равны ARM.
- [ ] **Э3. Тонкие обработчики в таблицы данных** (71 из 132; метод — как `native-dialog-hooks.csv`). КТ (авто): паритет по сценам, где они встречаются.
- [ ] **Э4+. Толстые подсистемы по порядку из Э1.4** (персонажи, камера, эффекты, поток/переменные, карта, звук, экран/видео), затем ходьба/физика/загрузка/меню/головоломки. Шаги и КТ дописываются после Э1.4.
- [ ] **Э-финал. Выключение ARM** на сценах, где перенесено всё; запасной путь — ARM по сцене.

## Порядок и зависимости

Э1.1 → Э1.2 и Э1.3 (независимы, можно по очереди) → Э1.4 → Э2 → Э3 → Э4+. Э2 можно начинать до Э1.4, если Э1.1 покажет, что порядок не зависит от прочих подсистем.
