# 🔬 Разведка: ndskit на нашем дампе

> Проект: `Sunpetal (рекомп)` · План: [План](PLAN.md) · Аналоги: [Существующие рекомпы DS](PRIOR-ART.md) · Дата: 2026-10-24

Прогнал готовый рекомпилятор `ndskit` (MIT, Python + C++) на дампе Europe `YHNP`. Цель: понять, насколько сложен код игры для статического рекомпа и сколько можно взять готового. Сырые данные: `docs/recon/` в репозитории `~/Developer/games/sunpetal`.

## Итог одной строкой

**Код игры рекомпилируется и собирается.** ARM9, ARM7 и 5 оверлеев с кодом превращаются в C++ за 40 секунд, всё компилируется, а сверка 542 функций ARM9 (из 2128) с интерпретатором на 8537 тестовых наборах дала **0 расхождений**. Основной риск не в CPU, а в графике и железе (рантайм у `ndskit` рассчитан на OpenGL 4.5, которого на macOS нет).

## Что за игра внутри

| | |
|---|---|
| Заголовок | `FSR`, код `YHNP`, версия 0, SDK 4.1 (NitroSDK, CodeWarrior) |
| Размер | 64 МиБ, занято 0x3676007 байт, 6674 файла в 255 папках |
| ARM9 | образ 0x6E258 (≈450 КБ), RAM 0x02000000, вход 0x02000800, без сжатия |
| ARM7 | образ 0x26DD8 (≈160 КБ), RAM 0x02380000 |
| Оверлеи ARM9 | 8 штук (0, 2, 7 пустые, по 0x20 байт), ARM7 без оверлеев |
| Secure area | расшифрована |

Оверлеи 1, 3, 4, 5, 6 содержат код: 440, 142, 58, 7 и 15 функций. Все лежат по одному адресу 0x020A0520 и подменяют друг друга. Самый большой оверлей 1 (76 КБ), остальные небольшие.

## Поиск функций (`discover`)

| | ARM9 | ARM7 |
|---|---|---|
| Функций | 2128 (1666 ARM, 462 Thumb) | 943 (934 ARM, 9 Thumb) |
| Инструкций | 78 346 | 37 564 |
| Таблицы переходов (switch) | 61 (857 целей) | 40 (706 целей) |
| **Не найдено целей косвенных вызовов** | **264** | **42** |
| Конфликтов | 0 | 0 |
| Время | 3 с | 0,6 с |

Про 264 косвенных вызова ARM9: это `blx r0..r12` и `mov pc, ...` (указатели на функции, виртуальные методы C++, обратные вызовы). Основная часть (`blx r1` 74, `blx r3` 48, `blx r2` 33, `mov pc` 30). Для статического рекомпа это главная трудность: `ndskit` решает её запасным интерпретатором в рантайме. С учётом оверлеев ARM9 суммарно получилось 2973 функций (после второго прохода по целям, которые вызывают другие оверлеи).

Про «неклассифицированные» байты ARM9: около 192 КБ из 450 КБ основной области не отнесены ни к коду, ни к данным. Скорее всего это код, до которого никто не дошёл статически (вызовы через таблицы виртуальных методов) плюс данные. Это надо исследовать отдельно, пересчёт после добавления оверлеев уменьшает его (в оверлее 4 до 76 КБ).

## Генерация и сборка

- `python -m ndskit.recomp ROM --out ...`: **7 модулей, 4578 функций, 203 839 инструкций, 37 файлов, 18 МБ C++**, 40 с.
- Все модули собираются clang на macOS без ошибок (ARM9, 5 оверлеев, ARM7).
- Сверка с интерпретатором (`selftest --cpu 9 --auto`): 542 функции (228 работают на одном стеке, 314 ещё с указателями-аргументами), **8537 векторов, 0 ошибок**.
- Это сверка с интерпретатором самого `ndskit` (не с melonDS), поэтому ошибки декодера, общие для обоих, она не поймает. Сверка с melonDS (сейвстейты) есть в `ndskit`, но мы её не запускали.

## Что не получилось (и почему это нормально)

- Рантайм `ndskit` не собрался на macOS «из коробки»:
  1. `coro.cpp` использует `ucontext` (на macOS нужен `-D_XOPEN_SOURCE=600 -D_DARWIN_C_SOURCE`, с этим флагом собирается);
  2. рендерер требует заголовки OpenGL 4.5 (`GL/glcorearb.h`), а macOS поддерживает максимум GL 4.1. Графику нужно писать заново, это и так в плане (wgpu).
- Запустить игру целиком мы пока не пытались. Для этого нужен рантайм железа DS, который будет нашим на Rust.

## Что это значит для Sunpetal

1. **Рекомпиляция процессорной части выглядит решаемой.** Весь код собирается, а 542 проверенные функции из 2128 ARM9 (25%) сходятся с интерпретатором. Остальные 1586 пока не проверены.
2. **Что брать у `ndskit` (MIT):** разбор картриджа (`rom.py`), форматы (LZ, SDAT), поиск функций (`discover.py`, лучший образец для CodeWarrior-кода), эмиттер C++ (`emit.py`), идею запасного интерпретатора, сверку с сейвстейтами melonDS. Лицензия MIT совместима с Apache-2.0, нужно сохранить копирайт `ndskit` в файлах, откуда брали.
3. **Запасной интерпретатор обязателен** для 264 косвенных вызовов и кода, который игра копирует в RAM (ITCM и т.п.).
4. **Оверлеи** держим как отдельные модули с таблицей «какой оверлей сейчас в 0x020A0520», как делает `ndskit`.
5. **Железо и графику** пишем на Rust: 2D-движки, GX (3D), звук, DMA, таймеры, IPC. Нужные образцы: `ndskit/runtime/*.cpp` (MIT) и документация GBATEK; `dust` (GPL) только для чтения идей, не для копирования.
6. Сгенерированный код пока **C++** (как у `ndskit`). Решение «начинаем с C» применимо к нашему собственному рекомпилятору; `ndskit` как прототип выдаёт C++, это нужно учесть.
