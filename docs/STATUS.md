# Статус Sunpetal на 2026-10-24

Рекомпилированная DS-версия игры исполняется на Rust-рантайме без эмулятора внутри: от точки входа через заставки и меню до вступительной сцены, с картинкой и звуком (пока в безголовом режиме: PNG и WAV).

## Что есть

| Часть | Где | Состояние |
|---|---|---|
| Рекомпилятор ARM/Thumb → C | `tools/ndskit/` (форк Python-части ndskit, MIT) | работает; 4578 функций, 203 839 инструкций ARM9 и ARM7, оверлеи отдельными модулями |
| Шов C ↔ Rust | `crates/sunpetal-runtime/include/sunpetal_abi.h`, `docs/ABI.md` | готов; быстрый путь памяти в C |
| Интерпретатор ARM/Thumb | `src/interp.rs` | проверен теми же векторами, что и рекомп |
| Планировщик и потоки SDK | `src/sched.rs` | сопрограммы (`corosensei`), кванты по виртуальному времени, переключение контекста, ожидание процессора |
| Оборудование | `src/nds/` | регистры, таймеры, DMA, IPC, прерывания, картридж и сохранение, SPI/RTC, VRAM, тайминг |
| BIOS | `src/bios.rs` | SWI, вход в прерывание, прямая загрузка |
| 2D | `nds/gpu2d.rs` | оба движка в программном виде |
| 3D | `nds/gx.rs`, `nds/render3d.rs` | геометрический движок и программный растеризатор |
| Звук | `nds/sound.rs` | 16 каналов, захват, микшер; WAV |
| Запуск без экрана | `sunpetal-headless ROM --vblanks N --shots/--shot-every --input --wav` | PNG обоих экранов, скрипт кнопок и касаний |
| Окно | `crates/sunpetal-app` (`winit` + `wgpu` + `cpal` + `gilrs`) | два экрана двумя текстурами, раскладка данными (4 штуки, F2), фильтр (F3), звук в устройство, клавиатура, геймпад, мышь как тач; 59,8 кадра/с; тест раскладки |

## Проверки

`cargo test -p sunpetal-runtime` (12 тестов, ~45 с; `boot` и `reaches_the_save_data_menu` нужны `SUNPETAL_ROM`):

- 542 функции ARM9 игры (8537 векторов), 198 функций оверлеев (3095) и инструкционные тесты ARM9 (3749 функций, 29 724 вектора) и ARM7 (3547, 28 057) сходятся с интерпретатором `armemu`, и то же через наш интерпретатор. Расхождений нет.
- Планировщик на функциях хоста: переключение контекста, кванты, спящий процессор.
- Запуск игры: на 300-м кадре логотипы, на 1500-м меню «SAVE DATA» (после START), звук с ~20-й секунды.

Результат на дампе (START каждые 100 кадров с 400-го): логотипы → титул → меню «Hello!! SAVE DATA» → вступительная поездка по мосту.

## Что не сделано

- Окно не проверено вживую дальше заставок (снимок окна на заставке верный; управление, звук на слух и геймпад не пробовал). Нет меню настроек, масштаба внутреннего разрешения 3D (рендер всегда 256x192), полноэкранного режима, сохранения положения окна.
- 3D: туман, контуры, сглаживание, теневые полигоны, битмап задней плоскости. 2D: мозаика, захват дисплея, вывод из основной памяти. Звук: сложение канала захвата со следующим. Всё названо в логе запуска.
- Сохранения: формат файла есть (EEPROM/Flash по `.sav`), экспорта и импорта нет.
- Этапы 6–12 плана: настройки, пакеты текстур из PS2, эффекты, перевод, платформы, релиз, моды.
- Этап 0: проверка названия по WIPO/EUIPO/USPTO (вручную), изучение `ndsrecomp` (только чтение), PS2-образ в нужном виде.

## Известные вопросы

- Горизонтальные полосы на части кадров вступительного ролика (например, 1350-й): ошибка рекомпа или времени? Эталона (savestate melonDS) нет.
- Дорога в сцене на мосту выглядит блочной: проверить фильтрацию и перспективу текстур.
- Шум на 24-й секунде звука и работа звука в устройстве: проверить на слух.
- Скорость: программный рендер с отрисовкой каждого кадра идёт со скоростью ~227 кадров/с (3,8 раза быстрее реального времени) на сцене с 3D; окно держит 59,8 кадра/с. На тяжёлых сценах запас может быть меньше.
- `arm_context_saved` и разматывание до основания потока проверены только на функциях хоста, не на живых потоках с `OS_SaveContext`: игра идёт, значит работает, но отдельного теста нет.
