# Перевод (этап 9): разведка, 2026-10-26

Читалось: проект перевода `~/Developer/games/fsar-ru` (только чтение) и наш рантайм.

## Что есть в проекте перевода

- Таблица `text/ru.csv`: колонки `Глава, Сцена, ID, Русский`, 13 879 строк. Исходный английский лежит в других колонках `text/dialogue.csv`.
- Конвейер: таблица → `scripts/insert.py` (переписывает сценарии `decoded/.../<сцена>.s` в `patched/`, обычные UTF-16 `.txt` в `patched_raw/`) → `scripts/build_rom.py` (сжимает LZ10, подставляет файлы в NitroFS, собирает ROM через `ndstool`).
- Кириллица: четыре шрифта NFTR (`scripts/make_ru_font.py`, `fontio.py`, `nftr.py`), подписи спрайтов и страницы Guide/LostList перерисованы (`scripts/gfx_*.py`, `patch_state_gfx.py`).
- Ограничения текста: предел строки 188 px, правила `text/STYLE.md`.

## Что отличается от оригинального ROM

Сравнение `extracted/data` и `build/data`: из 6666 файлов отличаются **795, всего ~1,7 МБ**.

| Тип | Файлов |
|---|---|
| `.z` сценарии (сжатые, LZ10) | 658 |
| `.txt` (2D, EdoComment, Profile) | 131 |
| `.NFTR`/`.nftr` шрифты | 4 |
| прочие `.z` (2D) | 2 |

То есть перевод целиком сводится к замене файлов NitroFS. Кода (ARM9/ARM7/оверлеев) он не трогает.

## Как игра получает файлы у нас

`nds/cart.rs` отдаёт игре байты образа ROM (команды карты по адресам), поэтому NitroFS читает сама игра; `nitrofs.rs` разбирает FAT/FNT только для отладочных инструментов. Значит слой перевода можно сделать на уровне образа: виртуальный ROM = оригинал + заменённые файлы.

## Предлагаемая схема (проект, не решено)

1. **Слой замены файлов вместо хука на строки.** Рантайм получает таблицу «путь файла → новые байты». Для каждого заменённого файла в виртуальном образе обновляется запись FAT (начало, конец), а сами байты дописываются в конец образа. Раскладку остальных файлов не двигаем, так что ограничения на рост файла (`layout_lock.py` у `fsar-ru`) нам не нужны: в `fsar-ru` он нужен только для старых сейвстейтов эмулятора.
2. **Распространение без текста оригинала.** Сценарии содержат структуру оригинала, поэтому в дельте хранить собранные файлы нельзя. Хранить:
   - для сценариев и `.txt`: таблицу строк (ключ = файл + ID, хеш оригинальной строки, русский текст); рантайм/компоновщик читает оригинальный файл из ROM, применяет замены (порт `insert.py` + LZ10-сжатие на Rust или Python в компоновщике) и кладёт результат в слой замены;
   - для шрифтов и картинок: бинарную дельту к файлу ROM (и/или набор правок), чтобы не включать данные оригинала.
3. **Где применять.** В компоновщике на ПК при сборке `sunpetal.data` (этап 9б): готовый слой попадает в архив. Режим «подсунуть ROM» без `sunpetal.data` перевод не применяет, либо применяет в приложении тем же кодом (общий крейт), если дельта лежит рядом.
4. **Проверка совпадения.** Хеш оригинала каждого файла/строки; несовпавшее остаётся оригинальным.
5. **Несколько языков.** Каждый язык — отдельная часть архива с таблицей и своими шрифтами; выбор в настройках. Для не-русских языков оригинальные английские тексты берутся из ROM (в ROM есть En, Fr, De, Es, It, смотри `lang` в путях, например `ue`).

## Решения и открытые вопросы (уточнено 2026-10-26)

- **Решено: запасной путь обязателен.** Если `sunpetal.data` нет и пользователь подсовывает ROM DS (и дельту перевода рядом), приложение само применяет перевод. Значит разбор `.s`, правила вставки (порт `insert.py`, `scriptfmt.py`) и LZ10 (сжатие и распаковка, порт `lz10.py`) пишутся на Rust в общем крейте, который использует и приложение, и компоновщик. Объём небольшой: парсер `.s` 19 строк, вставка около 100, LZ10 83 строки.
- **Решено: язык оригинала — английский EUR.** Перевод сделан с английского текста европейского ROM, подменяется каталог `ue`. Сверка с нашим дампом остаётся как проверка (хеши `extracted/data` против нашего ROM), а не как вопрос.
- **Решено: хуки на строки в памяти не нужны.** Русский перевод уже работает заменой файлов (в эмуляторе), текст берётся из файлов. Хук остаётся запасным только для других языков, если там найдутся строки, собираемые кодом.
- **Проверено: состав графической дельты** (сравнение EUR ROM и `fsar-ru/build/fsar-ru.nds` от 2026-10-26 по файлам NitroFS; набор из 6666 файлов тот же, отличаются 795). Распакованные данные, байты, отличающиеся от оригинала:

  | Группа | Файлов | Размер оригинала | Отличается | Оценка дельты (XOR + zlib) |
  |---|---|---|---|---|
  | Guide (страницы справочника) | 48 | 4,77 МБ | 12% (560 КБ) | ~340 КБ |
  | LostList | 20 | 1,06 МБ | 17% (179 КБ) | ~140 КБ |
  | 2D (интерфейс) | 10 | 0,50 МБ | 14% (71 КБ) | ~67 КБ |
  | Шрифты NFTR (4 файла) | 4 | ~62 КБ | ~10%, файлы выросли на 264 байта | десятки КБ |

  Вывод: графика переведена **не целиком**, 83–88% байт остаются оригинальными (фон, рамки, неподменённые части). Значит в дистрибутив нельзя класть сами файлы, а нужна дельта (бинарный патч), которая сама по себе картинок оригинала не содержит. Общий размер оценочно около 550 КБ графики плюс таблица строк. Сжатие файлов `.z` пересобирается компоновщиком после применения патча к распакованным данным (сравнение «как есть» по сжатым байтам бесполезно: совпадает 5–10%).
- **Прецедент:** `fsar-ru/release/fsar-ru.xdelta` уже распространяется как патч к ROM (с контрольными суммами `CHECKSUMS.txt`).
- **Формат дельты:** свой простой бинарный патч для распакованных файлов (копирование и вставка фрагментов, как IPS/VCDIFF) либо готовый крейт; решить при реализации. Для текста (сценарии, `.txt`) остаётся таблица строк.
- **Решено (права):** перевод принадлежит автору проекта, в дистрибутив идёт дельта без текста оригинала.
