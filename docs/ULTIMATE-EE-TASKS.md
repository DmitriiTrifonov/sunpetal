# Задачи для агента `sunpetal-ee`: выгрузка для ультимативной версии (2026-11-11)

Кому: агенту проекта `~/Developer/games/sunpetal-ee`. Откуда: план `sunpetal/docs/ULTIMATE-IMPORT.md` (этап «У»). Формат строк — как в `notes/queue.md`: одна задача = один результат + автоматическая проверка. Автор переносит строки в очередь сам; номера `X-NN`, чтобы не пересекаться с `Q-NN`.

## 1. Зачем

`sunpetal` (рекомп DS-версии) подменяет модели, анимации, текстуры, звук и видео на PS2-качество. Разбор PS2 живёт у вас; `sunpetal` пишет собственный читатель на Rust **по вашим описаниям** и сверяет его с вашей выгрузкой. Поэтому от вас нужны три вещи:

1. **Эталонная выгрузка** в стабильном формате (`out/export/v1/`), по всему образу, с хэшами.
2. **Описания форматов**, достаточные, чтобы написать читатель без вашего кода (`notes/formats/*.md`): смещения, типы, правила, ссылки на F-NN и адреса ELF.
3. **Закрытие «?»**, от которых зависит импорт: T4, цвет вершин, `SceneScale`, интерполяция, роли VU-программ, звук, `ipum`.

Ваши правила остаются: писать только в `tools/`, `notes/`, `out/`, `extract/`; `sunpetal` и `fsar-ru` — только чтение; каждый экстрактор проверяется на всех файлах типа; гипотезы помечаются `?`.

## 2. Контракт `out/export/v1/`

Общее: UTF-8, LF, числа в TSV и JSON десятичные (смещения — `0x…` строкой), углы в радианах, id ассета = первые 10 hex SHA-1 тела (как в `models.tsv`), плюс полный SHA-1 в манифесте. Выгрузка детерминирована: повторный запуск даёт те же байты.

```
out/export/v1/
  manifest.json            схема 1; sha1 ISO и ELF; дата; sha1 каждого скрипта tools/; счётчики по типам; список файлов с sha1
  models/<id>.glb          glTF 2.0: узел на кость, жёсткий скин, примитив на материал
  models/<id>.json         сырой паспорт модели (см. ниже)
  models/<id>.vtx.bin      сырые массивы для побайтной сверки (см. ниже)
  motions/<id>.json        сырые ключи GIM
  textures/<sha>.png       RGBA; альфа GS 0x80 → 255
  textures.tsv             sha, w, h, psm, sha картинки, sha палитры, все вхождения (файл#запись.entry)
  scenes/<R>.json          БД сцены в разобранном виде
  events/<R>.jsonl         вызовы методов с константными аргументами
  audio/…                  см. X-21…X-24
  video/…                  см. X-25
  shaders/…                см. X-13…X-17
  refs/…                   эталонные кадры, см. X-20
  text/<R>.tsv             число реплик по блокам (без текста), см. X-06
```

`models/<id>.json`:
- `sha1`, `size`, `scene_scale`, `occurrences[]` (`файл#запись@смещение`, слот: `Scene3D.GIG | GIG4 | GIG5 | Chara.GIG | GIG2 | extra`);
- `objects[]`: `type`, `joints[]` {`index`, `parent`, `child`, `next`, `std` (StandardJointNo), `init_key` [px,py,pz,rx,ry,rz], `flags`};
- `materials[]`: `tex0` (сырой u64 hex), `tbp0`, `cbp`, `psm`, `tw`, `th`, `tcc`, `tfx`, `clamp`, `prim` (сырой), `pass` (0/1/2), `texture` (sha из `textures.tsv` или `null` + причина), `gs_state` (id из `shaders/gs_states.tsv`);
- `series[]`: `object`, `pass`, `material`, `prim_type` (`strip`/`list`), `first_vertex`, `count`, `bones` [до 3 индексов костей из DMA-тегов];
- `bbox` в позе `InitKey`, счётчики вершин и треугольников.

`models/<id>.vtx.bin` (little-endian, без заголовка, порядок = порядок серий в файле): на вершину `f32 pos[3]` (локальные оси кости, до `SceneScale`), `f32 nrm[3]`, `u8 rgba[4]`, `f32 st[2]`, `u8 bone_slot` (0..2), `u8 pad[3]`. Это главный эталон для сверки читателя.

`motions/<id>.json`: `sha1`, `bone_type`, `n_std`, `stp_table[]`, `range` (кадров), `joints[]` {`flag`, `child`, `next`, `keys[]` {`frame`, `flag`, `pos`?, `rot`?}} — **сырые ключи, без пересчёта и интерполяции**; `occurrences[]` (`файл#запись`, `MotionID`).

`scenes/<R>.json`: `scenario_id`, поля `WDataBaseLocal`; `scene3d[]` {`index`, `record`, `gig`, `gig4`, `gig5`, `tblock`, `gil`, `focus`, `tables` (сырые смещения)}; `chara[]` {`index`, `record`, `gig`, `tblock`, `gom`, `gom_tblock`, `gig2`, `blink`, `name_id`, `walk/run/idle/quickwalk/fastrun` (MotionID)}; `motion_pack[]` {`motion_id`, `motion` (id)}; `tasks[]` {`index`, `func` (имя из ELF)}; `vab_id`.

`events/<R>.jsonl`: строка на вызов: `event`, `pc`, `class`, `method` (имя), `x`, `args[]` (константы со стека; `null`, если аргумент вычисляется), `seq` (порядковый номер вызова в событии). Нужны все классы, включая звук.
